# DaoYun 后台视觉改版

## Problem Statement

如何在不改变后台业务逻辑和操作流程的前提下，让站长更快识别信息、完成管理操作，并获得克制、专业、简洁的视觉体验？

## Recommended Direction

采用“编辑部工作台”作为视觉基线，结合“数据控制台”的信息密度和“柔和分层”的空间层级。

整体以中性浅灰背景、白色工作区域、细边框和少量品牌绿色构成。减少重复卡片、装饰性标题和过大的导航间距，让列表、筛选、状态和操作成为视觉重点。

这次改版只建立统一的后台视觉语言，不修改权限、接口、路由和业务流程。

## Design Principles

1. 内容优先：装饰不得抢占管理信息的注意力。
2. 层级明确：页面、区域、列表和操作依靠排版区分。
3. 紧凑可读：提高密度，但正文不低于 14px，辅助文字不低于 12px。
4. 操作稳定：主要操作位置、按钮层级和危险操作样式保持一致。
5. 主题完整：亮色与深色使用同一套语义令牌。
6. 响应式一致：覆盖 320px、768px、1024px 和 1440px。

## Visual System

### 页面框架

- 页面背景使用中性浅灰。
- 主内容区域使用白色或主题表面色。
- 普通区域依靠细边框分层。
- 阴影只用于浮层、弹窗和重要悬浮区域。
- 内容最大宽度统一，避免不同模块左右跳动。

### 顶部栏

- 高度控制在 52–56px。
- 弱化当前厚重的深绿色色块。
- 保留品牌、返回社区、当前账户和主题控制。
- 品牌色只作为识别元素，不铺满整个界面。

### 侧边导航

- 宽度从 244px 收紧至约 216px。
- 导航项高度控制在 40–44px。
- 使用 Lucide 图标、文本和清晰的选中状态。
- 当前模块使用浅品牌背景、品牌色文字和窄侧边指示条。
- 移动端改为紧凑模块选择入口，避免承载 11 个横向标签。

### 页面标题

每个模块统一包含：

- 模块名称。
- 一句简短说明。
- 必要的状态或数量摘要。
- 右侧主要操作。

标题区不使用独立大卡片，不重复显示“站点管理”。

### 列表

- 由重复卡片改为结构化列表行。
- 桌面端保持稳定的信息列和对齐关系。
- 移动端折叠为标题、摘要、状态和操作。
- 使用分隔线建立节奏。
- 悬停使用极浅品牌背景。
- 选中行使用清晰但克制的品牌色状态。
- 状态徽章缩小，避免胶囊标签泛滥。
- 行内操作默认弱化，悬停或选中后增强。

### 筛选工具栏

- 搜索框作为主要控件。
- 状态筛选、排序和辅助操作保持紧凑。
- 工具栏与列表在视觉上属于同一区域。
- 移动端自动换行，不产生横向溢出。

### 编辑表单

- 采用单列阅读流，必要字段局部双列。
- 按“基础信息、显示设置、高级选项”分组。
- 标签位于控件上方。
- 帮助文本和错误信息拥有稳定位置。
- 输入框、下拉框和文本域使用统一高度、圆角与焦点环。
- 保存操作位于稳定的底部操作区。
- 危险操作放入独立区域，不与保存按钮并列竞争。

### 密度与尺寸

- 正文：14px。
- 页面标题：20–22px。
- 分组标题：15–16px。
- 辅助文本：12–13px。
- 控件高度：36–40px。
- 普通圆角：6px。
- 面板圆角：8px 以内。
- 列表行垂直内边距：10–12px。
- 页面横向内边距：桌面 24px，移动端 12–16px。

## MVP Scope

第一阶段覆盖能够建立完整视觉语言的五类页面：

1. 后台整体框架、顶部栏、侧边导航和主题令牌。
2. 工作台摘要与待办列表。
3. 用户管理列表与详情工作区。
4. 举报队列与详情双栏。
5. 版块列表与编辑表单。

同步整理通用样式：

- 页面标题。
- 筛选工具栏。
- 列表行。
- 状态徽章。
- 表单分组。
- 按钮层级。
- 空状态、错误状态和加载状态。
- 深色主题。
- 响应式布局。

## Success Criteria

- 站长能够在列表中更快区分标题、状态、时间和主要操作。
- 相同类型的操作在不同模块中具有一致视觉位置。
- 页面不再依赖大量独立卡片建立层级。
- 亮色与深色主题不存在明显对比度或品牌色冲突。
- 320px 至 1440px 范围内不出现关键操作溢出。
- 不修改现有接口、权限判断、路由状态和业务行为。
- 现有组件测试、类型检查和生产构建全部通过。

## Key Assumptions to Validate

- [x] 站长更偏好紧凑列表，而不是当前卡片式展示。
- [x] 216px 侧栏仍能完整容纳中文模块名称。
- [x] 更弱的顶部品牌色不会降低后台与社区的识别联系。
- [x] 用户、举报和治理模块能够共享同一套列表视觉规则。
- [x] 仅调整视觉结构就能带来足够明显的效率改善。

## Risks

- `src/styles.css` 中后台样式集中且相互影响，改版需要分阶段验证。
- 运行时品牌色允许自定义，顶部栏和状态颜色不能依赖固定深绿色。
- 部分辅助文字当前只有 9–10px，统一放大可能影响高密度布局。
- 移动端后台模块较多，仅改变视觉样式可能无法彻底解决导航效率。

## Not Doing

- 不修改后端接口、DTO 或数据库。
- 不重构权限体系。
- 不替换现有 Hash 路由。
- 不新增富文本编辑器。
- 不增加批量操作、列排序或传统分页。
- 不重做业务流程和字段结构。
- 不引入大型组件库。
- 不使用玻璃拟态、大面积渐变、大圆角和过度阴影。
- 不把所有内容都包装成卡片。
