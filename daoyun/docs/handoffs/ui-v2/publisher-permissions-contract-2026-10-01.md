# UI V2 发布器附件权限补充契约

日期：2026-10-01。对应 DYV2-010 / P-02 / P-07；继续执行冻结方案，独立记录服务端权限补全，不修改冻结九文件。

## 前端能力来源

- 使用现有 GET /api/v1/boards/{slug} 的 viewer 能力，不在版块摘要新增字段，不新增端点、依赖或第二套编辑器。
- 每次版块、账号或 CSRF 作用域变化重新查询。等待或失败期间限制写入；查询可重试，正文、标题和已选图片继续保留。迟到响应不能恢复旧权限。
- 不可创建主题时限制发布及上传；仅不可上传附件时仍允许纯文本。保留已选图片并提示明确移除或切换版块，不能静默丢弃图片。

## 服务端重新绑定

- 主题创建、主题编辑、回复创建和回复编辑共用 bind_rich_content_attachments。仅在引用尚未绑定主题的附件时，重新检查当前账号 attachment.upload 标准权限及目标版块对应限制。
- 已有同主题的图片可继续编辑；仍检查上传者归属、主题归属、ready、clean、未删除及现有有效期/草稿引用规则。权限撤销不放宽这些有效性条件。
- 不重复消耗上传配额；沿用 verify_community_action_with_executor 的无配额验证。拒绝在现有事务中回滚主题、正文、附件绑定及已消耗主题配额。SQL 错误仍原样传播。
- 沿用公开错误契约：正文附件不可用返回 422 request.validation_failed，字段 rich_content。版块禁止创建主题返回现有 403 board.posting_restricted；私有草稿中的不可用附件仍返回 409 draft.attachment_unavailable。没有修改 DTO、OpenAPI 结构或数据库迁移。

## 本轮验证

- 真实生产页面和重建 API 验证首页、版块、独立浏览器上下文云草稿入口，均使用同一 rich_content/board_id 写入模型，直接发布，无强制预览。
- 真实页面从允许上传的版块切换到禁止附件的版块，正文和图片保留，上传与带图发布受限；直接绕过页面提交返回 422。只读版块的直接发布返回 403；移除图片后的纯文本仍可正常发布。
- SQLx API 用例验证版块限制和群组权限拒绝后的事务回滚；他人、未上传完成、待扫描、感染、扫描失败、过期、删除、已绑定其他主题的附件均不能写入主题或私有草稿。有效 PNG 签名之后附加 EICAR 内容用于独立验证扫描拒绝。
- 验证结果及剩余边界见 eighth-increment-verification.json；本补充契约不代表 G0–G5 或真实手机键盘已通过。
