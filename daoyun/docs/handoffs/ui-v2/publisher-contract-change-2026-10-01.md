# UI V2 发布器九图写入契约变更

日期：2026-10-01。对应 DYV2-010，依据冻结方案的九图、单张失败重试和顺序持久要求；本地工具执行已获授权。

## 写入约束

- 现有 v1 主题、回复与正文修改共用富文本校验器。图数从 20 收紧为 9，包含嵌套引用和回复门控中的 image 节点；重复引用仍逐节点计数。
- 私有草稿写入将 images 数组与 rich_content 中 image 节点合并计数，上限 9。超限返回原有 422 request.validation_failed，不更新草稿版本，不绑定附件或创建主题。
- DraftContent.images 的 OpenAPI maxItems 为 9；说明同时明确正文与数组的合计限制。没有新增端点、字段、数据库迁移或第二套编辑器。
- 现有读取不裁切已保存的服务端正文。旧数据需要调整到九图以内后才能再次写入，不自动迁移或静默丢弃。

## 顺序与恢复

- 上传前为每个选择文件保留位置。失败、取消和重试都使用原位置；正文按最终数组顺序追加附件引用，服务端草稿保存同一数组顺序。
- 未完成图片阻止发布与云端草稿切换。已上传附件与正文继续保留；单项可重试或明确移除。
- File 字节仅驻留内存，不进入本地 JSON、服务端 DTO 或日志。关闭/刷新后保留本机恢复标记，必须重新选择文件；处理完成后继续同步。这些恢复标记不是云端附件。
- 账号或草稿作用域变化取消旧上传，迟到结果不进入新作用域。上传有显式取消操作；取消后可逐项恢复。

## 验证边界

- 浏览器覆盖五宽度的失败重试、按钮/键盘排序、刷新恢复、九图名额、取消和发布跳转；写操作使用路由 mock。
- 隔离 SQLx API 测试覆盖实际上传、草稿保存/读取、超限拒绝、顺序发布、附件绑定与授权媒体投影。其中一张实际上传，其余八张为隔离数据库中的附件夹具。
- 完整真实浏览器写入链路、跨标签页冲突、过期会话与真实手机键盘仍待验收；不把分开的 mock 浏览器与真实 API 测试当作同一真实 E2E。
