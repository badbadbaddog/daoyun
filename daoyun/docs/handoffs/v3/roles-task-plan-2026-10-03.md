# DYR-012 管理团队实施约束

依据用户已授权的 DaoYun_V3 完整任务方案、02 执行计划 DYR-012、03 界面规范及 A10/A11 原型实施。DYR-002/007/010 已完成。DYR-011 最终后端复验已完成；本卡前端、保护审计与最终验证均完成，结果见 team-roles-2026-10-03.md。

## 目标与验收

- 职务模板只组合实际权限目录中的完整键集合；目录缺少任一键时禁用模板，不部分保存。保留自定义角色、系统角色只读与 revision 冲突草稿。
- 人员搜索按需读取，确认显示人员、角色、版块/全站、exact/subtree 和实际期限。当前模型支持 subtree；未支持的到期任命明确禁用，不提交虚假期限。
- 管理团队消费 scope_id 链接，按任命版块、角色、精确用户名筛选与分页，展示当前加载条数及真实范围。
- 分离角色读写、任命读写、人员检索能力；高危权限改动单独确认，确认前无写入。保留同步重复提交防护。
- AC-012-01：仅 A 版任命实际操作 B 版内容返回 403，不能通过界面扩大。
- AC-012-02：验证已支持的 exact/subtree；全站不支持 subtree，任命期限不支持且清楚说明。
- AC-012-03：系统最高管理任命不可撤销/修改；拒绝时保留管理员与审计。现有权限上限防止赋予操作者不持有的能力，增加本人任命拒绝的定向覆盖。

## 实施顺序

1. 先补现有页面的失败行为测试：模板、scope_id 消费、人员预览与能力边界。
2. 增加模板数据与人员任命组件，接入团队页、精确 scope_mode 映射、筛选 URL 与高危确认。
3. DYR-011 后端复验完成后，再补授权保护审计与本人提权拒绝的 Rust 定向测试。
4. 真实请求验证 A/B 范围、子版、系统角色保护；桌面/手机、键盘、axe、版本冲突及取消不写入。
