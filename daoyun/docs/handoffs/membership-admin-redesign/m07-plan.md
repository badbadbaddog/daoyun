# M07：角色、版块权限与权限解释

状态：2026-10-07 用户回复“继续”，按本具体规格完成并暂停；结果见[m07-result.md](m07-result.md)。M01–M07已完成，M08不在本阶段、未开始。

## 目标与授权依据

沿用已接受的 membership-permissions-core-v2.md 和 M01 阶段边界。角色/任命仅决定治理能力；用户组和权益仍决定普通能力与 MAX 额度。账号最终拒绝优先，不在前端重算授权。

## 具体契约

1. 保留现有五项普通检查，增加治理查看已发布主题、置顶、精华、锁定、移动五项只读检查。治理查看对应 moderation.topic 的实际查询条件；不声称能够读取待审、隐藏状态或已删除主题，不新增隐藏内容 capability。
2. 治理动作必须由后端按当前角色任命、instance/site/board scope、exact/subtree 和当前版块树判断。移动还需目标版块标识与两端权限；治理缺少主题/目标时返回缺少上下文，不返回最终允许。矩阵的用户组治理行不适用。
3. 增加账号状态、基础组/附加组身份、角色任命及 scope 来源字段。任命保留真实长期事实，不编造到期、启停或快照版本；角色修订独立于权益快照版本。所有来源总数上限 128；超过则拒绝完整诊断，不截断伪装完整。
4. 指定用户矩阵与权限检查增加 authorization.roles.read 读取门槛，与现有七项读取能力共同保护角色权限明细。纯用户组矩阵仍只需要用户组和内容策略读取能力。读取权限撤回立即隐藏旧结果。
5. READ ONLY / REPEATABLE READ 中使用现有权限表及 daoyun_board_scope_covers；复用治理写路径的同一权限谓词，保留其锁定行为。检查不写审计、额度、积分、EXP、任命或业务资源；真实操作仍执行 revision、范围、状态和并发鉴权。
6. 人话层按账号 → 基础组 → 附加组 → 权益 → 治理任命 → 资源条件展示；技术层默认折叠，含原因码、权限键、来源 ID、角色/策略修订及 scope。额度只归于普通能力。未知字段/原因不能伪装允许。
7. 角色页保留系统角色只读、授权上限、任命保护、修订冲突和高风险确认；说明作用域与范围，长期任命不暴露契约实现细节。版块访问策略明确治理主体只是访问条件，不自动提供治理动作。
