### 必须保留的已有边界

- ADR-008：兑换、运营报表与投票优先官方插件；官方插件使用与第三方相同的批准、沙箱、配额与审计协议。
- 标准权益插件停用不会导致历史权益自动失效。
- 积分扣减和标准权益授予当前各自独立提交，不能在 UI 或插件中简单串联以冒充原子兑换。
- 会话 last_seen_at 不是历史活跃数据，不能用于精确 D7 留存。
- 搜索只扩展现有后端过滤，不重写全文搜索。
- 草稿附件存在到期清理；服务端草稿必须与附件引用共同设计。
- 投票权限在 crates/infrastructure/src/community_groups.rs 已存在；不能根据未命中的检索误判为缺失。

## 任务执行方式

每个任务先阅读即将修改的确切代码，先写失败行为测试，再实现并运行定向测试。
每个任务仅处理所列职责，预计超过 5 个文件时拆分契约、持久化、接口、UI 小任务。
下列文件为定位锚点；新增模块优先独立文件，避免把三个插件塞进大文件。
所有写入都遵循既有事务内鉴权和审计规范。

## 第一阶段：兑换

### E1：定义受控原子兑换契约

- 接点：crates/api-contract/、crates/plugin-host/、固定宿主扩展 API 与领域事务。
- 验收：定义输入输出、权威商品引用、允许数据范围、稳定错误、幂等与配额；不能任意指定受益人和价格。
- 验证：契约反序列化、未知字段/能力拒绝、固定 API 与 OpenAPI 一致性测试；本阶段不扩展 WIT。
- 依赖：规格审阅。

### E2：实现兑换事务与收据

- 接点：migrations/、crates/infrastructure/src/membership.rs、standard_entitlements.rs、新兑换模块及测试。
- 验收：一次事务完成价格/限次校验、扣分、权益、收据、审计、Outbox；同键重放，异参冲突。
- 验证：PostgreSQL 并发扣减、下架/改价、限次、失败回滚、正反迁移。
- 依赖：E1。
- 若提取已有账本/权益事务函数，保留原接口并先运行原回归。

### E3：官方兑换插件和宿主接入

- 接点：plugins/official-points-redemption/、能力批准、固定 API 查询与安装包构建。
- 验收：商品管理使用宿主管理、按 provider_key 隔离的持久化与 revision；请求不能绕过能力批准；停用停止新兑换。

### E4：管理员商品流程

- 接点：会员后台挂载、商品管理组件、固定 API 客户端及组件测试。
