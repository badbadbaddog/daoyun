# 社区运营工作区实施计划

关联规格：`docs/specs/community-operations-workspaces.md`

## 增量一：接口契约与失败测试

- 在 `api-contract` 增加勋章操作记录、分页响应、撤销请求和撤销结果 DTO。
- 在 API 集成测试中先覆盖记录查询、撤销、重复撤销、公开资料同步和权限拒绝。
- 在 OpenAPI 测试中固定两个新路径。
- 运行目标测试并确认因接口尚不存在而失败。

## 增量二：服务端闭环

- 在基础设施层从 `admin_audit_log` 查询勋章操作记录，并联接目标用户和操作人。
- 增加事务化撤销：权限检查、目标用户检查、删除当前持有关系、写审计。
- 在 API 层增加参数校验、错误映射、OpenAPI 注解和统一响应 envelope。
- 运行 Rust 格式化和相关 API 测试，确认增量通过。

## 增量三：前端契约与失败测试

- 在前端 API 客户端增加操作记录查询与撤销方法，并严格校验服务端响应。
- 在管理页面测试中先覆盖工作区切换、操作记录显示、撤销交互与权限边界。
- 运行目标组件测试并确认新行为失败。

## 增量四：会员运营工作区

- 将现有页面拆成成长、积分、勋章三个可访问的工作区。
- 勋章工作区加入操作记录筛选、分页、撤销原因输入与确认反馈。
- 复用 DaoYun 语义颜色、紧凑间距和不超过 8px 的圆角。
- 在 320、768、1024、1440 宽度检查布局。

## 增量五：验证与提交

- 运行 `cargo fmt --all -- --check`。
- 运行相关 Rust 测试，随后运行 `cargo test --workspace`。
- 运行 `pnpm test`、`pnpm typecheck`、`pnpm build`。
- 在真实浏览器中验证工作区、网络请求、撤销流程、控制台和响应式布局。
- 使用代码质量技能复核鉴权、事务、错误语义、可访问性和无关改动。
- 分两个原子提交：服务端闭环、前端工作区。
