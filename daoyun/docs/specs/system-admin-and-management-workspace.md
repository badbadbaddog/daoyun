# 系统后台与管理工作台拆分规格

> 状态：已被 [ADR-007](../decisions/adr-007-unified-site-administration.md) 取代。保留本文用于记录历史决策，不再作为新实现依据。

## 决策

现有混合“管理后台”拆为两个职责明确的入口：

- `/#admin` 是独立系统后台，不渲染社区顶栏、社区左右栏、页脚或移动端社区导航。
- `/#management` 是社区内管理工作台，继续使用社区布局，面向版主与日常治理运营人员。

两个入口复用现有 `GET /api/v1/admin/access` capability 清单和现有管理 API。客户端只负责按 capability 展示入口与功能，服务端继续作为最终授权边界。

## 功能归属

| 入口 | 功能 | 读取权限 |
| --- | --- | --- |
| 系统后台 | 品牌配置、板块管理 | `admin.configuration.read` |
| 系统后台 | 会员经济 | `membership.rules.read` |
| 系统后台 | 角色与权限 | `authorization.roles.read` + `authorization.assignments.read` |
| 系统后台 | 运维监控 | `operations.read` |
| 系统后台 | 插件管理 | `plugins.read` |
| 管理工作台 | 举报处理 | `governance.reports.read` |
| 管理工作台 | 风控告警 | `governance.policy.read` + `governance.alerts.read` |

系统后台不得加载举报与风控数据；管理工作台不得加载品牌、板块、会员、授权、运维或插件面板。写操作继续检查现有细分 capability、会话和 CSRF。

## 页面结构

### 系统后台

- 独立顶栏：产品标识、返回社区、当前账号。
- 固定左侧导航：按 capability 展示系统功能。
- 主工作区：当前模块标题、说明和已有管理面板。
- 桌面端采用传统论坛后台的紧凑信息架构；移动端把左侧导航折叠为可横向滚动的模块导航，页面本身不得横向溢出。

### 管理工作台

- 保留社区顶栏、左右栏、页脚和移动端导航。
- 主栏标题改为“管理工作台”，只显示“举报处理”和“风控告警”。
- 账户菜单按 capability 分别显示“管理工作台”和“系统后台”。

## 验收标准

- 直接访问 `/#admin` 时，系统后台可独立刷新并自行恢复会话。
- 从社区切换到 `/#admin` 或从系统后台返回社区时，无需整页刷新。
- `/#admin` 与 `/#management` 的标签集合严格按上述职责隔离。
- 仅治理权限账号可以进入管理工作台，但不能看到系统后台功能。
- 仅系统权限账号可以进入系统后台，但不会触发举报列表请求。
- 320、768、1024、1440 像素宽度无页面级横向溢出，导航可使用键盘，页面 heading 与 navigation 具备明确可访问名称。
- 现有管理写入、权限判断、错误态和 CSRF 行为保持不变。

## 非目标

- 不修改服务端 API、数据库或 capability 定义。
- 不复制 phpwind9 的品牌素材或具体视觉资产，只采用独立后台的信息架构与紧凑排版原则。
- 不在本切片新增后台模块、权限继承规则或移动端原生应用入口。
