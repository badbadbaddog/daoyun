# 用户、成长、权益与治理核心 V2 实施计划

## 总览

按风险和依赖顺序先纠正成长事实来源，再建立社区权限与治理作用域，随后提供标准权益投影和业务插件宿主。每个任务保持可独立验证，不把运营玩法并入核心。

## 架构决策

- 现有 Points 账本保留为可消费事实；新增 EXP 账本，不复用 `lifetime_points`。
- 新增 UUID 动态等级表；运行时不解析 `internal_key` 推导等级序号。
- 社区用户组与 RBAC 角色分表、分服务、分 capability。
- 子树治理按当前板块树动态求值，不维护后代授权缓存。
- VIP、签到、任务、勋章认证和运营玩法走新版本插件契约；核心只提供标准权益、事件、命令、存储和 UI 基座。

## 检查点

- 第一阶段后：Points 与 EXP 完全分离，动态等级无硬上限，全量质量门禁通过。
- 第二阶段后：普通社区操作只由状态、用户组、权益和内容策略判定。
- 第三阶段后：治理 exact/subtree 与常用动作形成服务端闭环。
- 第四阶段后：插件可安全写入核心标准权益事实。
- 第五阶段后：至少用一个官方示例业务插件证明事件、命令、存储、任务和交互 UI 全链路。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 现有积分等级字段被客户端依赖 | 高 | 新接口加法发布，分切片迁移并在删除前显式弃用 |
| 板块移动导致子树授权泄漏 | 高 | 每次按当前树求值，禁止静态后代缓存并加入移动回归 |
| 插件命令扩大核心攻击面 | 高 | 每个 host import 独立 capability、Schema、配额、审计和幂等 |
| 多账本并发产生重复奖励 | 高 | 业务幂等键、账户行锁、追加式反向流水和事务 Outbox |
| 核心范围再次膨胀 | 中 | 使用 ADR-008 核心准入条件逐项评审 |
