# 会员经济与勋章目录管理

## 目标

根据 2026-09-05 用户要求，会员经济沿用后台统一的分区列表设计；勋章不再限制为固定 17 项业务目录，支持新增、编辑和删除。

## 行为与验收

- 成长、积分、勋章、用户组、权益维持各自工作区，移除重复标题和大面积嵌套容器。
- 勋章目录默认只显示列表；新增、编辑、手动发放、撤销按需打开弹窗；操作记录单独切换。
- 新增与编辑可配置名称、现有素材库中的图标、手动或累计积分自动发放。业务键由服务端生成，管理员无需填写。
- 删除须确认：从可发放目录移除并停止自动发放，保留成员已持有的勋章和审计记录；删除不是批量撤销。
- 列表、公开目录、用户持有展示从数据库读取名称和素材映射；现有 17 张图作为可复用素材，新勋章数量不受其限制。
- 创建、编辑、删除沿用勋章规则写权限、CSRF、事务审计；编辑和删除校验 revision，冲突保留表单。
- 四种支持宽度无横向溢出，弹窗支持键盘与关闭焦点恢复，提交中防重复操作。

## 实现顺序与文件

1. 数据表补充名称、素材键、版本与删除标记；扩展 infrastructure 的目录维护和公开查询。
2. api-contract 定义请求响应，admin 增补 POST/DELETE，修改公开目录及用户勋章映射，更新 OpenAPI。
3. admin.ts 客户端与 MedalsWorkspace 接入，MembershipAdminPanel 清理常驻表单，styles.admin.css 统一列表。
4. 行为测试、数据库集成测试、类型检查、构建与真实浏览器验证。

## 约束与代码风格

不新增依赖。数据库变更使用增量迁移，不修改已应用迁移；保留现有持有记录。此次使用现有素材库，不新增上传存储服务。DTO 位于 api-contract，组件使用 camelCase：`setRules(current => current.map(rule => rule.key === saved.key ? saved : rule))`。

## 命令与测试

`pnpm test`、`pnpm typecheck`、`pnpm build`、`cargo test -p daoyun-api --test membership`、`cargo test -p infrastructure --test membership`、`cargo fmt --all -- --check`。

测试先覆盖 CRUD 契约、名称和素材映射、删除后禁止再发放但持有记录仍可读取；再覆盖前端弹窗、保存失败保留草稿、删除确认与权限隔离。浏览器验证本地真实接口及 320/768/1024/1440px 布局。

## 验证结果（2026-09-05）

- 前端全套 83 个测试文件、635 项测试通过（限制为 2 个 worker，避免本地并行编译造成超时）；补充验证发放对象和撤销错误不会跨弹窗残留。
- API 会员集成测试 11 项、基础设施会员数据库测试 4 项通过，包含权限、CSRF、版本冲突、公开名称和素材映射、删除后持有记录保留。
- TypeScript、E2E TypeScript、生产构建、Rust 格式和 infrastructure/daoyun-api 全目标 Clippy 检查通过。
- 桌面与移动浏览器均通过真实创建、编辑、刷新持久化、确认删除；测试目录项已清理。
- 320/768/1024/1440px 无页面横向溢出；新增弹窗键盘关闭及焦点恢复正常；320/1440px 的弹窗 axe 检查无违规，并人工查看浅色、深色和移动端截图。
