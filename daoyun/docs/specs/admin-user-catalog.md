# 用户管理目录页

## 目标与验收
按参考图统一用户管理的统计、筛选、紧凑表格和详情。详情采用覆盖式抽屉，打开后列表宽度不变。用户请求及已确认的后台设计方向作为本轮范围。
- 四项已加载统计：总数、正常、已限制、已暂停。无全站数量接口时明确统计范围。
- 服务器搜索用户名/昵称/ID、状态、授权角色、注册日期；日期以浏览器本地日历为准，截止日包含当天。筛选保留在地址中；重置、刷新、20/50 条游标加载、失败重试。
- 表格展示用户、主要角色、状态、主题/回复/相关举报数、注册时间、最后活跃；勾选导出 CSV，防表格公式注入。
- 抽屉展示真实身份、公开资料、关注/粉丝、角色、限制、最近内容、相关举报、权限控制的审计记录；保留账号治理和角色调整的二次确认。
- 不伪造邮箱、电话、IP、等级、获赞或未激活状态；不添加无接口支撑的新增、删除、密码重置与批量治理按钮。

## 实现与边界
React/TypeScript；src/components/UserAdminPanel.tsx 与现有 API、Drawer、账号/角色操作组件复用。样式在 src/styles.admin.css 使用语义颜色和不超过 8px 圆角；测试在同名 test.tsx。不修改数据库、接口或引入依赖；保留已有工作区修改。
命名示例：export function UserAdminPanel() { /* typed state and named export */ }

## 执行与验证
先补失败行为测试，再实现表格及筛选，最后浏览器检查。运行 pnpm test、pnpm typecheck、pnpm build；Vitest 验证查询参数、日期边界、导出选择、加载与错误、抽屉。Playwright 验证 320/768/1024/1440、明暗主题、键盘及 axe。浏览器只读核验真实数据，治理写入由现有组件测试覆盖。

## 多角色复选框编辑
- 用户详情直接展示权限角色复选框，勾选仅改变草稿，保存后确认新增/移除清单才提交；可撤销草稿。
- 系统角色只读；自定义板块角色按角色与板块组合编辑，同角色可在多个板块生效。分页读取完整分配并精确匹配用户 ID。
- 沿用现有单项分配接口，逐项保存；部分失败时保留成功结果和未完成草稿，重新读取服务端分配后重试，明确提示部分成功。提交期间禁止重复操作或关闭确认。
- 用户身份标签、等级和会员不作为权限角色展示，不扩展权限接口或绕过系统角色限制。

### 多角色编辑验收

- 未对真实账号提交角色变更；写入、部分失败及恢复重试通过模拟接口行为测试验证。
