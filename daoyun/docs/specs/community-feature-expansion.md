# 社区功能扩展：积分兑换、运营数据、搜索、投票、草稿

## 状态与依据

Accepted — 2026-09-16，用户已确认开始实施；本文验收项完成前不表示已交付。

用户已选择上一轮建议中的 1、2、3、5、6。以下定义这五项的交付范围。
遵循 membership-permissions-core-v2.md、unified-post-community-v1.md 和 ADR-008。
积分兑换、运营报表、投票采用官方插件业务边界；核心保留权限、账本、审计、事务与受控公共能力。
搜索、草稿扩展现有内容链路。所有入口使用真实 API，不以浏览器本地数据冒充跨设备同步。

## 目标

- 成员使用积分获得有期限的标准权益，并查看兑换结果。
- 站长按明确口径判断社区增长、参与情况与积分收支。
- 用户组合筛选内容，分享搜索地址并恢复筛选状态。
- 作者创建单选投票，可访问内容的登录成员参与。
- 创作者保存多篇草稿，在不同设备继续编辑，旧版本不会静默覆盖新版本。

## 默认产品决策

以下是已确认的首版默认值：

- 兑换现有标准权益，不接入收费支付或自动续费。
- 商品包含名称、积分价格、权益类型及版本、有效天数、每人兑换上限和上下架状态。
- 权益从兑换成功时开始生效；同类权益仍生效时阻止重复兑换，避免重叠期限浪费积分。
- 运营数据采用 UTC 自然日，界面明确标注时区；支持最近 7、30、90 天。
- 投票为 2–10 个选项的单选，一人一票，不改票，最长持续 30 天。
- 投票成功或截止后展示结果，不公开投票者名单。
- 每人最多 50 篇草稿，保存正文、可选标题、版块、标签、图片和投票配置。
- 草稿不自动过期；无引用的临时附件继续按既有生命周期清理。

## 1. 积分兑换

### 用户流程

会员中心 → 可兑换权益 → 查看价格、权限与有效期 → 确认扣分 → 展示结果。
显示当前余额、所需积分和兑换后余额；余额不足、已有同类有效权益、下架或达到限次时显示具体原因。
提供本人兑换记录分页。成功后刷新余额、流水和权益；网络失败保留同一个幂等键重试。

### 管理流程

会员经济提供已启用官方兑换插件的商品管理入口。
管理员可新增、修改、上下架商品；编辑使用 revision，冲突后重新读取。
商品固定引用权益版本；之后修改类型或价格不改变历史收据及已授予快照。
商品管理与权益发布分别授权，不从积分赠送权限隐式扩大权限。

### 一致性

- 插件声明并启用固定业务扩展；宿主提供商品流程和扣分、发权益、记收据的受控原子操作。
- 复用现有官方补充说明、编辑审核的宿主扩展模式：按 provider_key 隔离持久化，能力批准后才开放固定接口。插件不能直接访问数据库或注册任意路由；本轮不新增通用 WIT 数据库命令。
- 不可简单串联两次现有的独立提交命令，避免扣分成功而权益失败。
- 事务内锁定账户，重新核对账号状态、商品版本、价格、有效性和限次，写扣分流水、权益、收据、审计和 Outbox。
- 价格、权益和兑换用户均来自服务端权威数据，客户端不能指定任意受益人。
- 任一步失败整笔回滚；成功但响应丢失时按幂等键返回原结果。
- 插件停用后停止新兑换，已发放权益继续生效，历史收据保留可查。
- 不改变 EXP，不允许积分或权益产生治理权限。

### 验收

- 并发和重试最多扣分一次、发放一次，不透支、不突破限次。
- 模拟权益、审计或 Outbox 写入失败，余额与权益均不变。
- 覆盖价格过期、下架、权限不足、已有有效权益的明确错误。
- 商品管理、用户兑换、历史记录形成真实浏览器流程。

## 2. 运营数据

官方运营报表插件使用受控聚合查询，不获取用户明细或数据库权限。
入口与运维监控分开，按独立读取能力授权。

| 指标 | 口径 |
| --- | --- |
| 新增用户 | 窗口内注册用户数 |
| 活跃用户 | 窗口内至少成功访问一次需身份认证业务接口的去重用户数 |
| 发帖量 | 窗口内首次成功发布的主题数 |
| 回复量 | 窗口内创建的回复数，不含主题正文 |
| 积分发放/消耗 | 窗口内追加流水正数之和、负数绝对值之和 |
| 版块活跃 | 窗口内各版块发帖、回复和去重参与人数 |
| 七日留存 | 注册后第 7 个 UTC 自然日活跃人数 / 已完整观察到第 7 日的注册 cohort 人数 |

- 增加按用户和自然日唯一的活跃事实，成功认证后 upsert，避免每请求一条记录。
- 不用会话最后访问时间反推历史活跃，不伪造留存回填。
- 展示采集起点、窗口、样本量；采集不完整或分母为零显示“数据不足”。
- 只将采集开始后、观察期完整的 cohort 纳入留存。
- 发布事件计数不因后续删除或隐藏倒退；若展示当前可见内容量，另行命名。
- 只回填现有事实可证明的历史；不可重建的区间明确标注范围。
- 采集失败不阻断登录、阅读、发布；故障区间标注数据不完整。
- 查询限定窗口，版块榜单限定数量，仅返回聚合值。

### 验收

固定时间样本覆盖去重、跨日边界、D7 分子分母、零样本和采集缺口。
未授权账号不可读取报表；刷新、窗口切换、空态和失败重试可用。

## 3. 搜索组合筛选

扩展现有搜索页和 topics 查询，不建立第二套搜索引擎。

- 内容筛选支持版块、作者用户名、标签、发布时间起止、最新/热门/活跃排序。
- 条件写入现有 hash 搜索 URL；刷新、前进后退、分享和分页保持一致。
- 关键词与筛选可组合，仅有筛选时也能查询内容。
- 内容专属筛选只作用于内容结果，并明确标注；保留现有其他分类的含义。
- 界面按日输入日期；服务端采用 UTC 起日包含、结束日次日零点不包含的边界。
- 服务端验证日期格式、起止关系、作者/标签和排序枚举。
- 条件变化重置游标，旧请求不能覆盖新条件；游标绑定完整筛选。
- 一键清除筛选，空结果保留条件。

### 验收

测试 URL 编解码、组合查询、日期边界、分页、清除和慢请求切换。
不能绕过已有版块/内容可见性、账号状态及拉黑读取边界。

## 5. 单选投票

采用官方投票插件，复用 COMMUNITY_PERMISSION_KEYS 中已有的 topic.poll.create，不建立同名平行权限。

- 发布器提供问题、选项和截止时间；插件未启用或无创建权限时隐藏入口。
- 主题作者创建投票；首票后不可修改问题和选项。
- 创建失败不能宣称成功；主题和投票的一致性通过受控宿主操作处理。
- 投票要求活动登录账号、主题与版块可访问、尚未截止、选项属于该投票。
- 最终权限、时间和重复票判断由宿主执行，不能信任插件 UI。
- 每人一条有效票；并发、重试及换选项重发不能重复计票。
- 主题关闭互动、隐藏、删除或用户受限后遵循对应拒绝策略。
- 截止后只读展示票数与比例；零票状态明确显示。
- 停用插件后禁止新建和投票，历史结果和审计保留。

### 验收

创建、参与、截止、结果展示贯通。
覆盖未登录、越权读取、跨投票选项、并发重复票、截止提交和首票后修改。
隐藏主题不得泄漏结果。

## 6. 草稿箱与跨设备同步

扩展现有 TopicComposer，不建立平行编辑器。

- 本人草稿列表展示标题或摘要、版块、最近保存时间，支持新建、继续编辑、确认删除。
- 服务端按会话用户隔离；列表分页，限制数量和体积，客户端不得指定 owner。
- 防抖同步，显示保存中/已保存/失败；断网保留本地恢复副本并可重试。
- 稳定 draft ID 与 revision；多设备冲突时停止覆盖，允许查看服务器版或另存本地副本。
- 切换草稿、用户、版块时隔离状态和请求。
- 旧本地草稿在本人继续编辑时导入，不静默丢弃或覆盖服务器草稿。
- 草稿图片保持私有，核对归属和状态；不得被临时附件到期任务误删。
- 删除草稿解除引用，只清理确实无其他引用的临时附件。
- 发布复用现有 posts/主题事务，包含 draft ID 和 expected revision，成功后原子消费草稿。
- 发布重试不重复发帖；关闭编辑器不等于删除草稿；未同步内容离开前提示。

### 验收

两个独立浏览器会话可继续同一草稿，并发编辑产生可恢复冲突。
跨用户读写删被拒绝；图片保存、恢复、发布、清理正确。
发布失败保留草稿，成功只产生一篇内容并清除对应草稿。

## 技术栈与结构

保持 React 19、TypeScript、Vite、Vitest、Rust/Axum、PostgreSQL、SQLx、Wasmtime，不新增依赖。

- plugins/：官方业务插件、manifest、Component、原生测试。
- crates/plugin-host/：声明固定扩展能力；沿用现有版本化业务 WIT，不增加通用数据库权限。
- crates/api-contract/：公共 DTO，不暴露持久化模型。
- crates/infrastructure/ 与 migrations/：事实、事务、权限、可回滚迁移。
- apps/api/：边界验证、路由、统一响应和 OpenAPI。
- src/api/：生成契约与运行时校验。
- src/features/、src/components/：页面及编辑器接入。
- e2e/：真实业务回归。

具名导出、语义样式令牌、Lucide 控件，复用既有错误、分页和 DTO 映射模式。

## 边界

- 始终：保存工作区原有修改，UTF-8，服务端最终授权，事务一致性，最小数据和真实验证。
- 单独决定：新依赖、变更 ADR-008、不可逆操作、生产部署、插件能力批准。
- 永不：插件直连数据库或任意路由、假统计、积分改 EXP、静默覆盖草稿、提交凭据。
- 通知偏好未被选择；支付、悬赏、多选投票、原生 App 不在本轮范围。
