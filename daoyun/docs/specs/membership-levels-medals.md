- 确定日期：2026-08-05
- 关联任务：P2 平台扩展能力中的积分账本、徽章、会员和经济系统
- 资源仅作为视觉素材使用；源目录中的旧论坛称谓不构成 DaoYun 的产品文案或权限语义。
- 已实现：资源归档、SHA-256 清单、公开资源目录 API、会员账户零余额初始化和追加式积分账本基础。
- 当前实现：数据库已将旧 `L1` 至 `L20` 一次性转换为 `lv_1` 至 `lv_20`；运行时只返回已开放等级，`lv_1` 至 `lv_6` 首期开放且阈值严格递增。
- 已实现：管理员积分授予具备 capability、CSRF、请求幂等、积分账本和管理审计；用户按累计积分自动升级，不会因扣减余额而降级。

## 目标

为会员用户组、用户等级和勋章建立稳定、可移植且不依赖旧论坛命名的资源约定：

- 有会员用户组时使用 `023\006` 图标族，用户组名称使用 `会员`。
- 图标作为等级使用时，运行时初始只开放 `Lv1` 至 `Lv6`；资源包中其余图标保留为后续扩展储备。
- 等级默认名称按 `Lv<序号>` 递增；管理员可自定义展示名称，但不能修改等级序号和稳定键。
- 勋章使用 `精品勋章4` 中的 `medal1.gif` 至 `medal17.gif`。
- GIF 文件内可能存在旧论坛文字；这些文字不能复制到 API 字段、页面标题、筛选项、通知或管理配置中。

## 决策依据

- 保留用户指定的图标和勋章视觉风格，避免重新制作素材造成视觉偏差。
- 采用数值序号和中性稳定键，将图片里不可控的旧名称与业务数据解耦，避免禁忌词汇进入 DaoYun 文案。
- 初始只开放 6 级，降低冷启动阶段的运营维护成本；资源与数据模型预留到 20 级，避免以后扩展时重排或重命名已发布等级。
- 会员组、等级和勋章分别表达身份、成长进度和荣誉收藏，避免用展示资源代替权限或账本事实。
- 通过固定文件映射和数量校验保证资源可追溯；外部桌面路径只作为来源，不成为部署依赖。

## 语义与命名

### 会员用户组

- 稳定键：`member`
- 展示名称：`会员`
- 图标族：本文件“初始等级图标映射”中的同一组素材
- 用户组与等级是两个独立字段：拥有 `member` 用户组不等于拥有某个等级，也不自动授予管理能力。
- 用户组的权限仍由现有授权模型控制，图标和展示名称不能参与鉴权。

### 用户等级

- 等级序号：`1` 至 `20`；序号是等级比较、阈值计算、审计和迁移的唯一依据。
- 稳定键：`lv_1` 至 `lv_20`；稳定键不参与展示，管理员不能修改。
- 默认展示名称：`Lv1` 至 `Lv20`；管理员可为每个已开放等级设置非空展示名称，空值回退到默认名称。
- 初始开放范围：仅 `lv_1` 至 `lv_6`。其余等级图标和序号仅作为储备，不出现在公开接口、用户资料或管理端常规配置中。
- 后续扩展：只能从当前最高开放等级的下一序号追加，例如 `lv_6` 后只能新增 `lv_7`；不能插入、重排、复用或降低已发布等级的序号。
- 文件映射按文件名升序一次确定；已发布映射不可因新增文件或文件系统排序差异而重排。
- 自定义展示名称不会改变稳定键、累计积分阈值、图标映射、权限或既有账本/审计记录；接口必须同时返回稳定键、序号和实际展示名称。
- 等级升级规则由积分账本和经济系统决定，本文件不定义积分阈值、降级规则或管理豁免。

### 勋章

- 稳定键：`medal_01` 至 `medal_17`
- 默认展示名称：`勋章 01` 至 `勋章 17`。
- 勋章与用户组、等级、权限相互独立；用户可以同时拥有多枚勋章。
- 勋章的业务授予条件由后续经济系统或运营配置定义，不能从文件名或 GIF 内文字推断。

## 实现约束

1. 资源导入时保留原始文件名和本文件映射，不按图片内文字重命名等级或勋章。
2. API 和前端只返回稳定键及 DaoYun 展示名称，不返回桌面绝对路径，不暴露资源包中的旧论坛称谓。
3. `member`、`lv_1` 至 `lv_20` 和 `medal_01` 至 `medal_17` 必须使用枚举或等价的服务端校验；未知键拒绝写入。
4. 资源文件缺失、重复或映射数量不符时，部署和资源校验应失败，不得静默回退到其他等级图标。
5. 资源落仓后增加清单校验，至少核对文件名、文件类型、数量和 SHA-256；桌面来源目录不作为生产依赖。
6. 任何会员、等级或勋章的授予操作都必须写入后续经济系统的账本/审计记录；展示资源不能替代授权或审计。
