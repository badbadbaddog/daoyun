# 帖子补充插件规格

## 交付目标

帖子补充是作者在原帖之后追加说明的独立内容能力。它不承担审核职责，也不复用编辑审核的配置、状态或队列。

后台路径：插件管理 → 安装帖子补充 → 确认安装 → 启用 → 补充设置。

## 已确认业务规则

- 作者可以在自己的已发布主题下追加补充；补充按时间展示在正文下方，不覆盖原文。
- 新补充保存后立即发布，不进入待审状态。
- 补充不能原地编辑。
- 每帖补充上限全站统一，默认 1 次，支持 0 至 100。
- 隐藏记录仍占用次数；降低上限不删除历史，隐藏不退还次数。
- 停用插件、卸载插件或关闭允许新增，只阻止新提交；已经发布的补充继续可读。
- 主题或回复编辑是否进入审核，由独立的编辑审核插件决定。

## 插件设计

官方清单声明 `topic.supplements` 与 `ui.panel`。真实 Wasm Component 只提供后台说明面板；宿主负责原生输入、设置、权限、计次和受控数据写入，插件不能直连数据库。

宿主按批准能力而不是插件 key 判定提供者。数据库通过唯一部分索引限制全站仅安装一个补充提供者。有效开关是全站设置 `enabled` 与插件启用状态的交集。

## 持久化与安全

新增时锁定帖子行，再校验作者、账号发帖权限、版块限制、锁帖、只读版块及内容可见性，串行计数并写入补充和审计，避免并发突破上限。

幂等键按帖子与作者隔离：相同正文重试返回原记录，不重复计数；同键不同正文返回冲突。成功提交后的幂等重放可返回原记录，即使随后停用插件，也不会创建新补充。

补充状态只表达内容可见性：`approved` 为公开，`hidden` 为隐藏。补充插件不提供预发布审核、驳回或审核恢复入口。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/api/v1/topics/{topic_id}/supplements` | 列表、配额 / 作者新增并直接发布 |
| GET / PUT | `/api/v1/admin/topic-supplements/settings` | 全站允许新增和每帖上限 |

提交正文为 `{"content":"补充说明"}`，长度 1 至 1000 个 Unicode 字符，需要登录 Cookie、CSRF 及 1 至 128 字符的幂等键。新建返回 201，重放返回 200。

设置示例为 `{"enabled":true,"max_per_topic":1}`。配置读写使用 `admin.configuration.read/write`。

列表 meta 包含 `request_id`、`enabled`、`max_per_topic`、`used_count`、`can_submit`。写操作要求 CSRF，业务响应保持统一 request ID，禁止共享缓存。

## 验收标准

- 补充插件启用且允许新增时，作者提交后立即在公开详情中可见。
- 补充插件停用后不渲染空的补充功能；已有公开补充仍展示。
- OpenAPI 不再暴露补充审核队列、补充审核动作或版块补充审核策略。
- 后台补充设置只包含全站启停和每帖次数，不出现审核入口。
- 并发提交、幂等重放、额度、停用后历史可读均有自动化测试。
