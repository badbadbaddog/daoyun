# 会员经济后台列表化设计

## 目标

将会员经济后台改为紧凑、可扫描、可直接增删改的运营列表。成长等级不向管理员暴露草稿、发布、停用或归档流程；新增与修改保存后立即在前台生效。

## 页面结构

- 顶部保留会员经济标题、等级总数和成长/积分/勋章任务标签。
- 成长等级使用单一列表容器；每行展示等级、名称、内部键、EXP 阈值、主题颜色和描述，不展示状态。
- “新增等级”位于成长等级标题区，打开独立表单弹窗；创建成功后立即生效并关闭弹窗。
- 每行显式提供“编辑”和“删除”。新增与编辑复用同一套表单弹窗；删除使用独立确认弹窗，确认后才调用删除接口。
- 表单弹窗打开后焦点进入首个字段，支持 Escape 关闭、Tab 焦点循环，关闭后焦点返回触发按钮；提交期间禁止关闭和重复提交。
- 勋章目录使用单一列表容器；每行展示图标、名称、资源键、累计积分阈值、自动授予开关、状态和保存操作。
- 积分授予和勋章操作记录保留表单/审计列表形态。
- 工作区不再使用带背景、边框和圆角的大卡片包裹。

## 技术与边界

- React 19、TypeScript、现有 CSS tokens、Lucide 图标。
- 不新增依赖，不改变现有读写权限键。
- 创建接口默认写入可用等级；新增 `DELETE /api/v1/admin/membership/levels/{level_id}`，沿用统一响应信封、请求 ID、会话鉴权和 CSRF 校验。
- 删除被会员使用的等级、删除后会破坏 0 EXP 起始等级或阈值顺序的等级时，接口返回可读的冲突提示，数据保持不变。
- 保留现有表单校验、异步状态和键盘标签导航。

## 验收标准

- 成长等级和勋章目录在 DOM 中分别暴露命名的 `list`，每个数据项是 `listitem`。
- 重复数据项不再形成独立卡片网格；同一目录内仅使用行分隔线。
- 页面不存在成长等级状态标签、状态字段、草稿/发布/停用/归档文案。
- 新增表单初始不渲染；“新增等级”打开命名为“新增成长等级”的模态弹窗，取消后不保留未提交内容；提交成功后列表出现新等级并显示“已创建并生效”。
- “编辑”打开命名为“编辑成长等级”的模态弹窗并预填当前值，取消不修改列表，保存后立即生效；“删除”必须二次确认，取消不会发请求，确认成功后从列表移除。
- 任一成长等级弹窗打开时，背景页面不可交互；弹窗具有标题、说明、明确的取消/提交按钮和完整键盘焦点管理。
- 保存勋章规则、积分发放和勋章撤销行为保持不变。
- 320px、768px、1024px、1440px 下无横向溢出；移动端行内容纵向重排，表单弹窗贴近视口底部并可在内部滚动。
- 页面无控制台错误或警告，相关测试、类型检查和生产构建通过。
