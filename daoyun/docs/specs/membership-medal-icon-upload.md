# 自定义勋章图标上传

## 目标与验收

用户已明确要求自定义勋章图标。本说明扩展 membership-medal-catalog-management.md 中仅限内置素材的范围。

- 新增和编辑弹窗仅提供上传 PNG、JPEG、WebP、GIF，不提供内置图标选择；新增必须上传，编辑可保留当前图标或上传替换。保留 GIF 原始动画和透明度。
- 单张最多 2 MiB、宽高最多 1024px，服务端识别文件真实格式后解码校验并限制解码内存；支持扩展名与真实格式不同的图片（如命名为 .jpg 的 GIF），使用真实 MIME 返回，拒绝 SVG、无效图片和空文件。
- 本地选择立即预览；保存时上传。失败保留草稿，成功上传后重试保存不重复上传；取消编辑丢弃本地图片选择。
- 复用 AttachmentStore 本地/S3 存储，不新增依赖。上传需勋章规则写权限、CSRF、审计；公开资源提供真实 MIME、nosniff 和缓存头。
- 素材以 SHA-256 内容寻址，数据库保存类型、大小及存储键。目录引用必须存在，旧图标保持可读，删除勋章后成员持有展示不破坏。
- 会员公开目录、主页、帖子勋章统一返回自定义图标 URL 和真实哈希。

## 顺序与范围

1. 增量迁移素材表及目录引用约束；infrastructure 新增上传/读取并校验素材存在。
2. api-contract 定义上传结果；API 添加上传和公开读取路由，统一素材 URL/哈希映射；生成客户端契约。
3. admin API 客户端、MedalsWorkspace 上传预览及错误处理、对应 CSS。
4. API/数据库与组件行为测试，真实浏览器上传、替换、刷新及响应式验收。

## 风格和边界

沿用命名导出、语义 CSS token、原生文件输入以及现有 ModalDialog。示例：`setEditor(current => current ? { ...current, file } : current)`。不新增依赖，不改已应用迁移，不删除旧素材或成员持有记录；必要数据库变更属于用户已授权功能范围。

`pnpm test`、`pnpm typecheck`、`pnpm build`、`cargo test -p daoyun-api --test membership`、`cargo test -p infrastructure --test membership`、`cargo fmt --all -- --check`、`cargo clippy -p infrastructure -p daoyun-api --all-targets -- -D warnings`。

测试覆盖权限、CSRF、格式/大小/尺寸、不存在素材引用、公开字节及哈希、保存失败重试、新增图标必填与编辑保留原图；浏览器覆盖 320/768/1024/1440px 和键盘操作。

## 首次上传功能验证结果（移除内置选择前）

- 83 个前端测试文件、638 项测试通过；上传预览、失败重试复用已上传资源、非法文件拒绝及切回内置图标均覆盖。
- 12 项会员 API 测试和 4 项会员数据库测试通过。新增测试核验重复上传、超限请求、请求编号、公开原始字节和 SHA-256、目录与持有展示、删除目录后图标仍可读取。
- 图片验证单元测试覆盖 PNG/JPEG/WebP/GIF、超限尺寸和字节数；Clippy、格式检查、TypeScript、E2E 类型检查与生产构建通过。
- 桌面和手机的真实浏览器测试通过上传、替换、刷新后展示及切回内置图标；四种支持宽度无横向溢出，320/1440px 的编辑弹窗 axe 检查无违规。
- 图片使用独立存储对象；同内容重复上传复用数据库记录并清理多余对象。保留已提交素材以支持持有记录和失败后的保存重试；取消本地选择不会上传文件。

## 文件格式误判修复

实际反馈的 `125D3H2KR50-23I46.jpg` 为 8222 字节、34×54px 的 GIF89a 图片。浏览器因文件扩展名声明 JPEG，旧实现按 JPEG 解码导致 422；弹窗又仅显示顶层“请求参数校验失败”，掩盖了图片字段原因。

修复后仍限制允许的上传类型，并根据文件签名识别 PNG/JPEG/WebP/GIF，以真实格式解码、存储 MIME 和提供公开响应。大小与尺寸校验保持有效。保存失败优先展示服务端字段错误并保留草稿。回归测试覆盖 JPEG 声明的 GIF 成功上传、真实 GIF MIME 返回、无效图片拒绝及字段错误展示。
