# 交给代码执行任务的任务书

执行主体由用户选择。此文件可提供给code/Codex任务或开发者，不强制FS、不创建会话、不自动部署。第一轮只执行DYR-001，完成基线后再按依赖逐项执行。

## 可直接粘贴的首个任务

```text
项目：DaoYun刀云。目标是在现有Rust/Axum/PostgreSQL与React/TypeScript/Vite上收敛体验，不重写。
请读取本交付包中的01-product-plan、02-execution-plan、04-contracts-and-migration以及现有仓库交接。
本次仅执行 DYR-001：基线复验与历史任务映射。
参考仓库badbadbaddog/daoyun，分支codex/daoyun-home-foundation，参考HEAD 40bcff25ec920912bff7f4472bc6174e63b8e2d9。
项目在仓库中的参考子目录为daoyun；本地路径由实际环境确认。若HEAD变化，报告差异，不强制checkout覆盖。

1. 确認实际Git根、项目根、分支、HEAD、工作树状态和历史交接。保护所有用户未提交改动。
2. 核对package.json、Cargo.toml、工具链、锁文件、环境依赖和已有生成脚本。
3. 用隔离测试数据库跑现有定向/全量门禁并分类记录：PASS、既存FAIL、环境BLOCKED；没有运行的标NOT_RUN。
4. 记录核心页面与六条旅程的当前状态、网络请求和截图。真实账号/密钥不可出现在文档。
5. 把DYR-001至030与历史任务映射，指出已实现/只需回归/确需修改的范围。
6. 输出本任务结果与当前交接，明确下一任务DYR-002及尚缺条件。

边界：不开始重构，不升级依赖，不清工作树，不删除测试，不使用生产DATABASE_URL，不提交无关文件。
如环境阻断，给出准确命令与错误证据，不写PASS，不执行未经授权的生产安装/迁移。
验收依据：AC-001-01至03。只有证据齐全才标DONE；本次任务不授权生产部署。
```

## 后续每个任务的执行循环

读交接→确认依赖和工作树→核对候选契约→补失败用例→最小实现→定向测试→相关回归→真实页面/API→记录证据→小范围提交或标未提交→更新交接。共享CSS/路由/api-contract由明确单一所有者合并；可并行的是隔离后的独立业务，不是同时重写同一组件。

第一批在G0通过后处理003草稿、004通知、005定位、006加载。不要从大规模改目录或更换组件库开始。007公共壳完成后再推进用户组、版块、团队和诊断；新规则与数据迁移必须单列审批。

## 每次回报固定格式

```text
任务：DYR-xxx / 状态：IN_PROGRESS、BLOCKED或DONE
基线：仓库/分支/HEAD/dirty摘要
完成：实际更改及路径
证据：命令、退出码、断言、截图/HAR位置
兼容：接口/数据/权限/旧链接/生成物检查
未完成：具体剩余项，不用“基本完成”替代
风险与回退：兼容范围、是否涉及新写数据
Git状态：未提交或具体提交；是否已部署单独记录
下一步：只写下一个可执行任务与所需输入
```

程序输出异常或页面不可打开时先停止标DONE。不要为了得到绿色测试临时旁路认证、伪造后端、关CSRF或用静态原型替代真实验收。
