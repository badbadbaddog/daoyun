# 验收、证据与发布门禁

本包`tasks/acceptance.json`与CSV包含120项待执行用例，90项逐任务最少用例和30项跨链路用例，均为NOT_RUN。它们是验收下限，不替代现有测试。原型检查另存证据，不得批量把应用用例改为PASS。

## 1. 测试层次

| 层次 | 要验证什么 | 证据 |
|---|---|---|
| Rust单元/特征 | 规则、时间边界、额度合并、状态转换 | 测试名称、命令、退出码、提交号 |
| Rust+隔离PG集成 | 权限、事务、竞争、幂等、迁移 | fixture、schema版本、结果断言 |
| API契约 | 状态码、错误封套、分页、版本、脱敏 | 请求响应断言（无凭据）、OpenAPI差异 |
| React组件 | 独立加载、错误、保存状态、焦点、筛选 | Vitest/Testing Library真实运行记录 |
| 浏览器链路 | 登录→浏览→发帖→讨论→管理→返回 | Playwright轨迹、截图、失败网络记录 |
| 构建与部署候选 | 基础/Wasm/S3、干净检出、兼容 | lock、artifact哈希、cargo tree、包清单 |
| 恢复与回退 | 数据、附件、密钥、幂等水位 | 隔离恢复日志与逐项检查 |

既有测试失败不能靠删测试、关权限或换假数据规避。基线已失败、环境阻断、新引入失败三类分别记录；必须阻断的P0故障不因“以前就坏”而自动放行。

## 2. 必备测试人物与状态

隔离fixture至少包含访客、普通成员、基础组不授权但附加权益授权者、到期/撤销身份、受限账号、暂停账号、仅本版版主、其他版版主、有限管理员和受保护的最终管理员。内容覆盖公开、受限、隐藏目录、待审核、已删除、父子版块与独立策略。

数量fixture包含55条未读而首批20条、分页之后才有未读、重复已读、全部已读并发新通知；额度包含0、10/20合并、最后1个额度竞争、到期恰好相等、非法负值/超大值。固定测试时钟，不靠sleep碰运气。

失败注入覆盖localStorage抛错、云端失败、成功响应丢失、图片部分上传、SMTP读取失败、单个会员/搜索接口失败、401/403/409、列表刷新失败、Wasm未编译/未配置/停用/故障、Redis或S3不可用。任何测试凭据只在隔离环境使用且不得写进公开交接。

## 3. 六条必过实际旅程

A. 访客浏览首页与版块→登录→回原位置→9图发帖→回复某楼→通知定位；B. 保存失败→拒绝误报→复制或恢复→重试；C. 编辑用户组→比较→冲突恢复→具体用户权限与实际动作一致；D. 从版块任命有限版主→只能管理授权范围→撤销立即按策略生效；E. 工作台直达举报→上下文→处理→审计→返回原筛选；F. 模块停用→新操作阻止→历史受限可读→恢复不重发奖励。

权限检查必须覆盖入口、正文、摘要、附件/缩略图、通知、搜索、缓存与旧链接。隐藏导航不算测试通过。响应中不应下载未授权私有字段再用CSS隐藏。

## 4. 页面与可访问性验收

320/390/768/1024/1440宽度检查主体不溢出、表单标签可读、状态不遮挡、焦点可见、键盘操作、200%缩放及错误提示。手机权限矩阵变单场景而不是整页挤压。主要操作目标按本方案44px设计，并检查WCAG 2.2目标尺寸相关要求及例外；原型没有完成屏幕阅读器和全WCAG认证。[S24]

列表空态、加载、局部失败、无权限、模块未启用、版本冲突、成功但刷新失败各自截图。每次拍图注明页面、宽度、角色、fixture与代码标识。截图不能含真实隐私/密钥。

## 5. 性能与复杂度对照

先测同一机器、相同数据、相同工具链的基线，再测候选。记录构建冷/热缓存、数据库缓存、并发、请求次数、传输体积、首屏可交互时间、核心API p50/p95、启动、空闲RSS和后台查询/任务数；至少多次采样报告中位与波动，不用一次快慢定结论。

硬目标是结构性行为：不进入积分页不请求流水；进入举报不等SMTP；版块详情不拉无用全站feed；停用可选任务不继续其专属查询；基础API依赖闭包不含Wasm。数值改善目标在DYR-001后冻结，不提前承诺内存降低50%或固定响应耗时。

不得用删除权限、关闭真实数据库、缩小fixture或暖缓存替换冷基线来获取改善。对轻量裁剪产生的安全/可维护性代价一并记录。

## 6. PASS定义与发布

每用例记录实际日期、构建/提交、环境、执行人或工具、期望、实际结果、证据路径。PASS必须有断言；FAIL保留原始输出；BLOCKED写具体缺失条件；NOT_RUN不等同失败也不等同通过。状态只更新实际执行项。

G0–G6门禁按执行计划；P0正确性、越权、数据损坏、锁死管理员、草稿误报、重复记账未解决时不可发布。可选SEO未执行记条件未启用，不伪装完成。相关全量测试、组合构建、独立干净检出与隔离恢复完成后才标发布候选。生产发布需要另行明确授权，不由交付原型自动触发。

## 7. 本次原型检查范围

本地单文件HTML使用Chromium加载文档内容，执行38页×5种宽度=190项页面/主体溢出检查及16项模拟交互检查，记录为原型检查。无远程请求、无真实应用服务与数据库。程序化DOM交互不等于在所有手机、浏览器和辅助技术上人工走查。详细原始结果在`evidence/prototype-validation.json`。

全部120项应用验收仍为NOT_RUN。UI atlas中的截图是原型渲染，不是仓库运行截图。
