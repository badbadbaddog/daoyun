# 官方帖子补充插件

## 在社区后台使用

1. 使用有插件安装权限的管理员账号进入「后台 → 插件管理」。
2. 在「帖子补充」条目点击「安装帖子补充」，核对权限后确认安装。安装后默认停用。
3. 点击「启用」，再点击「补充设置」。保留允许新增，设置全站每帖最多补充次数，默认 1 次。
4. 作者登录后打开自己的帖子，在正文下方提交补充；保存后立即公开。

补充设置需要配置读写权限。锁帖、只读版块、账号限制或次数用尽会阻止新增。

## 上传哪些文件

内置安装按钮已加载随网站分发的文件，不需要手工写 JSON 或调用接口。

手动安装时，使用插件管理的安装向导导入清单，再选择组件文件：

- 清单：`public/plugins/official-topic-supplements/plugin.json`。
- 组件：`public/plugins/official-topic-supplements/plugin.wasm`。

不是上传 Rust 源码、项目目录或 ZIP。后台条目提供清单和组件下载链接。

## 构建和部署

在项目根目录执行：

```sh
rustup target add wasm32-wasip2
pnpm plugins:build
pnpm build
```

构建脚本将插件源码编译为 WebAssembly Component，并将组件与清单放入上述 public 目录。前端生产构建会带上这些静态文件。修改插件后先重建插件，再构建并部署前端。

后端也必须更新并重启：启动时应用数据库迁移，包括 `202609060001` 和 `202609060002`。只更新网页、不更新后端，会导致新能力无法安装或使用。刷新浏览器后使用上述后台入口。

## 原理和开发边界

此插件声明 `topic.supplements` 和 `ui.panel`，使用现有业务契约 `0.1.0`。Wasm 提供后台说明面板，宿主根据批准的内容扩展能力开放原生补充表单和后台设置。正文写入由核心 API 完成，不把数据库访问权限交给插件。

没有扩展旧 WIT 的通用输入表单或帖子写入命令。这个包采用宿主管理的声明式内容扩展，不是任意插件都能自行写帖的通用 SDK 示例。判断依据是安装记录的能力和启用状态，不是官方插件 key；同一站点只允许安装一个补充能力提供者。

安装会打开全站允许新增开关，但插件仍默认停用。重新安装保留原有次数配置；卸载前需要停用。新增同时要求插件启用、全站允许新增、剩余次数充足以及服务端作者和版块权限校验通过。

补充不可由作者原地修改，每次发布都占用次数。补充不会覆盖原文，也不修改修订历史。停用或卸载不会删除历史补充，已发布内容继续展示。主题和回复编辑审核由独立的编辑审核插件负责。

## 源码入口

- `plugin.json`：清单、版本和所需能力。
- `src/lib.rs`：现有业务 Component 的导出实现。
- `Cargo.toml`：独立插件 crate。
- `../../scripts/build-topic-supplements-plugin.mjs`：构建及静态资源分发。
