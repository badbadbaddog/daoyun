## 0. 依据、现状与适用范围

本方案回答的是“如何把已有社区统一成一个可用、可维护的产品”，不是重新开发一套社区。

现状依据分三类：

| 依据 | 可以说明什么 | 不能说明什么 |
|---|---|---|
| 用户在本次对话提供的当前功能盘点 [P1] | 社区、会员、后台、插件与主题的已知业务范围 | 不能证明当前部署全部启用或测试通过 |
| 历史文件 `daoyun-current-stack-optimization-plan.md` [P2] | 原技术栈、不迁移框架、安全边界、旧路由兼容等既定约束 | 旧任务清单不能当作今天的未完成清单，旧路径必须重新映射 |
| 本次生成的六张界面示意图 [P3] | 浅色、蓝色、布局和内容展示方向 | 不是像素验收稿，也不是功能/API 依据 |

本次已尝试通过 FastSpider 查看可连接机器，返回机器离线；没有读取实时工作树、启动服务、运行项目测试、修改仓库或部署。计划中所有开发任务均为 `PLANNED`。执行时首先完成 DYV2-001。

参考项目路径：`C:\Users\111\Documents\Playground\daoyun`。实际 Git 根目录、分支、HEAD、源码目录和现有脚本必须现场核对，不能根据历史记录直接操作父目录。

历史技术基线为 React 19 + TypeScript + Vite，后端 Rust/Axum + PostgreSQL，插件 Wasm/Wasmtime。保持现场核对后的现有栈和锁文件版本；不在 UI 项目中顺带升级主版本。

### 0.1 冲突处理顺序

用户明确约束与安全/隐私边界 → 现场核实的业务契约 → 本方案正式决策记录 → 历史设计图与旧文档。

若当前代码与用户已明确规则冲突，记录差异并建立缺陷任务，不将代码中的缺陷视为应永久保留的产品规则。若只有装饰性字段缺失，删掉装饰，不为凑图新增业务系统。

### 0.2 本轮不可突破的业务边界

保留单一 Post/Topic 领域模型和统一编辑器；不因页面布局新建“图文帖”“交易帖”等业务类型。标题可空、正文优先、最多 9 张图片。首页不使用瀑布流。版块不是圈子，必须保留父子层级且不展示版块成员数。不增加交易字段、交易订单或单独的发布预览步骤。

EXP、积分、社区用户组、标准权益、勋章、治理角色保持独立；不能为了展示方便混成一个 VIP 体系。后端权限、配额、Cookie 会话、CSRF、审计、幂等、revision、附件访问与插件沙箱边界不降级。

## 1. 产品定位与改造目标

定位：**移动优先、桌面同样高效的内容发现型社区。**

首页负责发现；版块负责归属；详情负责讨论；个人主页负责公开身份；会员中心负责个人权益；后台负责治理和运维。

这轮解决五个问题：导航重复、帖子样式割裂、会员标识过载、后台模块难找、响应式与异常状态不一致。不能以更换蓝色色值、增加圆角和大横幅代替上述问题的解决。

### 1.1 成功标准

| 目标 | 可验收结果 |
|---|---|
| 浏览不迷路 | 任意核心页面有清晰位置；刷新、前进后退、楼层链接和返回列表有效 |
| 内容不割裂 | 图文/文字共享内容骨架，真实正文和图片不被强制改成另一种帖子类型 |
| 发布不繁琐 | 从版块发布默认选当前版块；标题可空；9 图排序、草稿恢复和失败重试可靠 |
| 讨论可持续 | 引用、楼层、回复对象、楼中回复、编辑审核状态有明确表达 |
| 身份有层次 | 信息流最多一个身份标签；公开主页不泄露私有会员资料 |
| 管理可追溯 | 操作对象、影响范围、原因、版本冲突和结果记录清楚 |
| 全站一致 | 六个核心页面深改，其余既有页面完成公共壳、组件与状态迁移 |
| 无业务倒退 | 原有主链路、授权、插件开关和主题偏好通过回归 |

不预设“活跃提升 30%”等无依据业务收益。上线后的使用数据用于复盘，不伪装成改造前已验证的效果。

## 2. 正式设计决策与示意图纠偏

以下是本方案采用的执行默认值，尚不代表用户已逐条审阅批准。后续变更须更新决策记录，不能凭另一张示意图偷偷变更范围。

| 编号 | 本方案默认决策 | 原因或边界 |
|---|---|---|
| D01 | 首页为单列连续内容流，非瀑布流 | 前面的双列示意图不作为实现基线 |
| D02 | 使用现有品牌蓝 `#2563EB` 的语义令牌 | 不为 V2 机械替换成近似蓝；保留已有品牌配置 |
| D03 | 浅色作为本轮主验收主题，保留已存在的深色/紧凑/高对比能力 | 不新扩主题市场，也不删除用户已有偏好 |
| D04 | 无图帖无媒体区域，不插假照片 | 需要固定封面的其他现有场景才使用带 DaoYun 标志的默认图 |
| D05 | Feed 只预览当前用户可访问的前 3 张图片 | 总图片上限仍为 9；受限图片不进入封面、计数和摘要 |
| D06 | 版块目录按真实层级组织，不使用成员数或“加入圈子” | 社区用户组后台的成员数属于另一实体，不受此展示禁令影响 |
| D07 | 浏览量未形成可信递增链路前，全站内容摘要默认不展示浏览指标 | 不填假值，也不把“未知”当 0 |
| D08 | 不新增封面编辑、最近访客、认证蓝勾、活动频道等示意图衍生能力 | 已有且可核实的能力另做映射；没有契约就不放可点击入口 |
| D09 | 公共主页默认只有主题和公开资料/身份 | 公开回复流须确认已有契约；收藏、草稿、积分流水不公开 |
| D10 | 发帖没有交易信息表单、没有强制独立预览步骤 | 交易相关描述仍由用户按站点规则写在正文中 |
| D11 | 后台工作台以待办为首，不放大型风景 Banner | 不把总浏览量、注册审核、插件可更新等未知数据塞进首屏 |
| D12 | 后台六个一级分组，保留所有既有功能和授权 | 工作台、内容、社区、会员、数据、系统 |
| D13 | 子版块导航表示进入子版块，不默认等于父版块内容聚合筛选 | 本版/含子版统计范围必须明确，不能仅前端拼当前页假聚合 |
| D14 | 页面能力通过现有配置、权限、接口共同判定 | 业务未启用、无权限、无数据、加载失败不能显示成同一状态 |
| D15 | 只做增量替换，不换框架、不重写后端、不一次性重写全站 CSS | 优先复用现有 Shell、Drawer、ActionMenu 和路由能力 |
| D16 | 响应式、键盘交互与权限测试在每项页面任务内完成 | 最后的回归不是第一次做手机版 |

### 2.1 范围分层

**本轮必须交付：**前台公共壳、首页、版块列表、版块详情、帖子详情与评论、统一发布器、个人主页与会员中心；搜索/收藏/通知/私信/账号安全的界面一致性；后台公共壳、工作台及现有各模块的组件迁移与核心操作回归。

**本轮按已有能力适配：**板块关注、公开回复流、封面、关联主题、特定后台趋势、插件投票/补充/审核/兑换/报表。G0 确认已存在则保留接线；未存在则不新增假入口，也不将其算作 UI 缺失。

**另立需求，不阻塞本轮：**个性化推荐、浏览量完整计量、现金支付/订阅/商城、第三方主题市场、原生客户端、最近访客、个人动态聚合引擎、版块社群成员系统、活动系统、Outbox 清理业务补全。

## 3. 用户与关键旅程

| 用户 | 首要目标 | 必须走通的路径 |
|---|---|---|
| 未登录访客 | 看内容、了解版块 | 首页 → 版块 → 主题 → 公开评论；需要操作时进入登录并可回原位置 |
| 普通会员 | 发帖、回复、找内容 | 从版块发布 → 上传/排序 → 发布 → 主题回复 → 通知回到具体楼层 |
| 作者 | 维护自己的内容 | 编辑 → 保存/待审反馈 → 修订记录；有帖子补充插件时追加内容 |
| 受限会员 | 理解限制原因 | 明确只读、额度不足、会话失效等状态，不出现提交后无解释的失败 |
| 版块治理人员 | 管理授权范围 | 后台待办 → 具体主题/回复上下文 → 处置 → 审计结果 |
| 平台管理员 | 维护站点和业务规则 | 会员操作、版块层级、角色权限、品牌/邮件/插件/运维 |

公开页面与本人页面必须是不同数据权限视图，而不是先把全部数据下载，再用 CSS 隐藏。

## 4. 信息架构与导航

### 4.1 前台

桌面顶栏：品牌、全站搜索、发布、通知、用户菜单。左栏：主页、社区、收藏；关注是首页的内容维度，可提供快捷链接但不能维护第二套关注页状态。会员中心、我的主页、草稿、账号设置放入用户菜单；已存在的入口保持可达。

移动底栏：**首页 / 社区 / 发布 / 通知 / 我的**。通知页面内提供通知与私信入口；不在底栏同时放消息、私信、通知三个近义入口。“我的”是本人快捷入口集合，不把他人的公开主页当个人控制面板。

栏目名称默认：对外导航“社区”，目录页标题“版块”，内容对象“帖子”，后台可保留原有“主题管理”。不重命名数据库或 API 的 Topic/Post 对象。

### 4.2 后台

| 一级 | 二级入口 |
|---|---|
| 工作台 | 我的待办、授权范围内的摘要、快捷操作 |
| 内容 | 主题、评论、举报、内容审核、风控告警 |
| 社区 | 用户、版块、角色与权限 |
| 会员 | 成长、积分、勋章、用户组、权益、兑换配置 |
| 数据 | 数据总览、运营报表 |
| 系统 | 品牌配置、邮件服务、插件管理、运维监控 |

展开当前分组，其他分组可折叠；当前页面不会因刷新失去高亮。没有权限的二级入口不出现，但服务端仍须独立授权。插件型入口按宿主开关、插件启用状态和当前用户权限共同显示。

### 4.3 路由规则

使用现有路由系统和地址形式；本方案中的页面名称是逻辑页面名，不承诺新的 pathname 或 hash。保留历史可复制链接、查询参数、楼层深链接和管理员直达地址。

排序、搜索词、版块、页码/游标等状态按现有安全契约持久化；返回列表恢复已加载内容和滚动位置。私信正文、草稿正文、密钥、会话令牌不进入 URL。

## 5. 视觉系统与布局规格

### 5.1 颜色与形态

优先将现有令牌映射到下列语义，而不是再创建一套互相覆盖的变量。

| 语义 | 浅色默认值/约束 |
|---|---|
| 品牌与主要操作 | `#2563EB`，复用站点品牌覆盖 |
| 页面底色 | `#F6F7F9`，允许映射到现有近似底色 |
| 内容表面 | `#FFFFFF` |
| 主文字 | `#17191C` |
| 次文字 | `#626B78`；仍需逐组合验证对比度 |
| 弱分隔线 | `#E6E8EC`；不得单靠浅线表达关键输入框/焦点边界 |
| 成长/积分强调 | `#C85516`；普通按钮不使用 |
| 危险/成功/警告 | 保留独立语义色，同时显示文字或图标说明 |
| 圆角 | 控件 6px，内容/弹层 8px；头像圆形例外 |
| 阴影 | 常规内容区默认不需要；菜单/弹层轻阴影 |

间距阶梯：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40px。该阶梯约束布局间距，不限制字体、图标、边框、百分比、内容自适应等合理尺寸。

不使用大面积渐变、玻璃质感、风景宣传横幅、多层卡片嵌套和全彩身份标签。图表及真实内容图片可有多色，但必须与界面操作色区分。

### 5.2 排版

系统字体优先，保留项目现有中文字体回退栈；不新增必须请求外部字体站的依赖。正文建议 16px，帖子长文 16–18px，行高 1.65–1.8；界面正文 14–16px，辅助信息 12–14px。标题依据层级约 20–28px。后台紧凑表格可以较密，但不压缩到难以点击和辨认。

标题、摘要仅在列表做行数控制；详情正文不能为对齐而截断。长中文、英文长词、URL、代码块、表格均有溢出策略。

### 5.3 响应式布局

| 宽度区间 | 布局默认值 |
|---|---|
| ≥1280px | 可用三栏：左导航约 176px，主内容自适应，辅助栏约 280px；栏间 24px |
| 1024–1279px | 左导航 + 主内容；取消辅助栏，关键动作不得随右栏消失 |
| 768–1023px | 简化导航/窄导航 + 主内容；根据空间收起非必要控件 |
| <768px | 单列；页边距通常 16px，320px 时可为 12px；移动底栏与安全区域 |

页面总容器最大约 1328px，外侧留白至少按当前断点处理；Feed 和阅读列通常不超过 800px。桌面顶栏约 60px，手机约 52px。这些是样式默认值而非所有页面必须三栏的硬要求：版块目录可为较宽主区，详情优先阅读。

验收宽度：320、390、768、1024、1440px。320 CSS px 重排、文本放大和键盘焦点可见性须独立验证；数据表格等确需二维布局的部分可局部横向滚动，不让整个页面横向滚动。[W2]

### 5.4 主题与密度兼容

保留已存在的浅色、深色、紧凑、高对比预设及本地偏好。当前组件不写死白底/黑字；品牌配置优先级沿用现有实现并在 G0 核实。V2 默认值不能覆盖站长的合法品牌设置。高对比模式中的有效控制边界、文字和焦点须实测；密度切换仅改变间距/行高，不改变内容和权限。

## 6. 组件架构

不要先造完整组件库再开发页面。先把一个真实闭环跑通，再按需要抽取共享能力。

| 层 | 组件职责 |
|---|---|
| 基础 | Button、IconButton、Input、Tabs、Select、Checkbox、Skeleton、EmptyState、Toast |
| 覆盖层 | ActionMenu、Drawer、ConfirmDialog、ImageViewer、Focus/Scroll 管理 |
| 前台壳 | SiteShell、TopBar、SideNav、MobileNav、PageHeader、RightRail |
| 内容 | UserIdentity、ContentExcerpt、MediaPreview、MetricBar、PostCard、TopicRow |
| 版块 | BoardBreadcrumb、BoardDirectoryGroup、BoardDirectoryItem、BoardHeader、SubBoardNav |
| 讨论 | TopicBody、CommentList、CommentItem、ReplyThread、ReplyComposer、RevisionNotice |
| 会员 | PublicIdentitySummary、GrowthProgress、PointsLedger、EntitlementList、MedalList |
| 后台 | AdminShell、FilterBar、DataTable、SelectionBar、DetailDrawer、ReasonField、ConflictNotice、MutationResult |
| 插件 | 现有宿主插槽的加载、权限、禁用、错误与历史内容容器 |

`PostCard` 与 `TopicRow` 可以是不同布局组件，但必须共享内容适配、身份、统计与交互原语。不要用几十个布尔参数把两者塞成一个不可维护的大组件。

已有 API 类型与客户端是唯一网络入口。由适配层生成仅用于展示的 view model；不要让页面自行拼接权限、重算服务器计数或直接手写新的请求契约。代码目录以现场映射为准，不为匹配本表强行搬家。

## 7. 全站统一行为契约

### 7.1 异步与权限状态

| 状态 | 页面行为 |
|---|---|
| 首次加载 | 骨架与真实结构接近，主内容标题保留，不显示伪零数据 |
| 已加载、空数据 | 说明暂无内容；允许的情况下提供发布/清除筛选入口 |
| 首次失败 | 可读错误 + 重试；需要排障时展示安全的 request_id |
| 加载更多失败 | 已有列表保留，在尾部重试，不回到空屏 |
| 401/会话过期 | 进入登录/恢复流程，保留安全的返回目标和当前未提交内容 |
| 403/无权限 | 不显示敏感正文、预览和私有统计；不能只禁用按钮 |
| 不存在/已删除 | 按现有服务端可见性语义展示，避免泄露受保护对象存在性 |
| 只读/额度不足 | 保留可读内容；明确不能提交的原因，不伪装成系统异常 |
| 409/版本冲突 | 保留用户输入，读取新版本、展示差异/重新编辑，不静默覆盖 |
| 429/频率限制 | 解释限制，按服务端提供的信息处理重试，不编造解封时间 |
| 插件未启用 | 公共入口隐藏或明确未开放；管理员可见配置入口但受权限限制 |
| 部分辅助区失败 | 隔离错误，主内容仍然可读和可操作 |

### 7.2 操作反馈

点赞、收藏、关注可沿用现有乐观更新，但必须处理失败回退、并发点击和最终服务器值。积分变更、版块合并、权限更改等高风险操作不得先显示成功再等待后端。

同一提交处理中防重复；发生超时结果未知时，沿用服务端现有幂等/状态查询机制，不直接换新请求号重发高风险动作。操作结果包含对象、结果状态、可追溯标识；不得把密钥、令牌和完整私信写入日志。

### 7.3 菜单、抽屉与键盘

复用一个可靠的覆盖层管理机制。打开弹层后焦点进入弹层；Tab 不跑到背景；关闭后返回触发控件或合理后继位置；Esc 按弹层语义关闭，未保存内容先明确确认。弹层外背景不可继续操作。[W4]

移动端抽屉通常全屏/近全屏，主操作固定但不能遮住最后字段；软键盘打开时避免底栏、评论条和发布栏三层堆叠。拖拽排序同时提供键盘/按钮移动方案。

## 8. 首页规格

### 8.1 结构

顶栏 → 推荐/关注/最新 → 单列连续内容流。宽屏右侧至多两组轻量辅助信息，例如已有数据支持的热门讨论和版块入口；不堆推荐用户、排行榜、横幅和推广图。

三种排序复用现有服务端逻辑。用户提供的推荐公式为 `8 × 主题点赞数 + 12 × 有效回复数`；本轮不修改权重、不宣称个性化推荐，也不依据可见一页内容在前端模拟全站热度。[P1]

### 8.2 PostCard 顺序

作者身份行 → 版块/时间元信息 → 可选标题 → 正文摘要 → 可选图片预览 → 统一操作行。

同一行的动作顺序全站一致：点赞、回复、收藏。浏览量在可信计量完成前默认不出现；不为不可用指标留下错位的占位图标。业务上需要不同动作的页可裁剪，但不能打乱已有动作相对顺序。

“统一位置”是指组件层级、对齐和动作顺序一致，不是强迫所有帖子同高度。内容少的文字帖自然更紧凑。

### 8.3 标题与图片

标题为空：直接展示正文摘要，不人为写入“无标题”。只有图片的合法帖子可以展示已存在的正文/说明；无描述时以可访问的图片区和作者信息承载内容，不虚构标题。

0 图：不渲染媒体容器。1 图：一个方形缩略图，默认最大宽度约 240px，不横向拉伸占满整页。2 图：两个方形缩略图同排。3 图：三个方形缩略图同排。4–9 图：只展示当前用户可访问的前三张，第三张显示剩余张数或总图数；数量语义需统一。

图片以真实顺序和授权后的缩略图来源渲染；不因“回复可见”或私有图片存在而泄露缩略图、文件名、alt 或数量。点击图片进入查看器；点击标题/摘要进入详情；点赞等按钮不会同时触发整卡导航。

### 8.4 列表状态

保留现有分页模型；加载更多按主题 ID 去重；切换推荐/关注/最新清理对应游标并隔离在途请求。返回列表恢复原筛选和位置；无关注内容时提供浏览社区入口，不制造“猜你喜欢”假推荐。

## 9. 版块列表规格

主区：页标题、搜索、真实分类/父版块、版块条目。没有业务分类实体时，不擅自创造“生活方式/数码科技/兴趣爱好”数据库分类；使用当前真实树形结构。

每个条目显示版块名称、短介绍、可见子版块入口，及有真实接口支持的主题数量/最近活跃信息。桌面可两列分组条目，手机单列；不做多层大卡片和首屏风景宣传图。

父版块可进入且可展开；子版块有独立链接。搜索结果显示完整路径，例如“技术 / 前端 / CSS”，不把不同父级的同名版块混在一起。只展示当前用户有权知道的节点、名称和计数。

“我的关注”“关注版块”仅在 G0 确认服务端已支持时保留；否则本轮默认不呈现，不把浏览器本地收藏假装为账号级订阅。

## 10. 版块详情规格

结构：面包屑 → 名称/介绍/允许的操作 → 子版块导航 → 置顶区 → 最新/活跃/热门/精华 → 紧凑主题列表 → 分页。

版块级置顶和全站推荐是不同概念，不能共享一个展示开关。子版块显示“子版块”标题和真实链接；默认主题列表只展示当前版块，若已有含子版块聚合接口则显式提供范围选项并说明统计口径。

主题行：标题或正文摘要、作者、时间、回复/点赞、可选缩略图、状态。置顶可集中为紧凑区域，超出默认可见条数可展开，但不能隐藏全部规则。没有标题的帖子依然可识别、可点击；不得强制补标题。

“发帖”自动选择当前版块；没有权限时不提供可执行提交入口，可显示只读/需要登录说明。版内搜索带版块上下文且不会默认扩大到全站。

移动子版块入口可换行或展开“全部子版块”，优先避免整屏横向滚动。不可把子版块藏到右栏后使手机无法进入。

## 11. 统一发布器规格

只保留一个编辑器：版块选择、可选标题、正文、图片、标签、必要的已存在访问设置、草稿状态和发布操作。

从版块进入默认选当前版块；从全站进入需选择有发布权限的版块。改变版块时重新获取能力限制，不能沿用旧版块的上传/发布权限。

图片最多 9 张，可上传、排序、移除、单张失败重试。每张显示上传中/成功/失败状态；仍上传或失败的图片不能被静默忽略后发布。排序若依赖正文块顺序，保持正文和附件引用一致；没有独立排序持久化契约时不可伪造仅本地顺序。

提供拖拽和“前移/后移”按钮；手机支持可理解的移动操作。附件归属、MIME、扫描/审核状态、公开可见性及大小上限继续由服务端校验。

本地与服务端草稿显示各自状态；不同账号、不同草稿和不同标签页不可互相覆盖。恢复冲突让用户选择保留版本，不用静默最新覆盖。草稿存储沿用现有安全策略；未发布私密内容不进入分析日志。

发布前失败保留正文和已成功附件。会话过期可恢复编辑上下文，重登后仍要重新校验版块/配额。发布成功进入真实帖子，列表数据失效刷新；不添加强制预览页面、不添加价格/成色/交易订单字段。

## 12. 帖子详情与讨论规格

### 12.1 帖子主体

面包屑、可选标题、作者、正文、标签、互动区、讨论区。正文是首要内容；宽屏右栏最多作者公开资料和所属版块，不重复堆四五个统计卡。

富文本按原有安全渲染器输出，保留段落、引用、列表、链接、图片、代码与已有插件块。正文图片按作者顺序显示，查看器可浏览全部有权访问的图片；禁止把同一批正文图片再在文末重复展示。

作者操作：编辑、删除、修订记录；其他用户：举报等当前已支持动作。分享优先复制真实链接；不存在的分享平台/渠道不放假按钮。

有编辑审核时，旧公开版本继续展示；作者/审核员可见权限范围内的待审提示。不得将待审正文当新公开内容缓存到首页、摘要、搜索或分享预览。

### 12.2 讨论区

每条一级回复显示作者、正文、固定楼层标识、时间、点赞、回复和更多操作。排序只提供已有 API 支持的模式；本轮默认使用现有时间顺序，不为示意图添加“最热”伪排序。

楼中回复视觉最多一层缩进；更深关系用“回复 @某人”和引用预览表示，不改变后端 parent/reply 关系。按需展开子回复，不一次性加载全部讨论。

楼层是稳定标识而非当前页索引；分页、排序和删除不重新编号。打开楼层深链接需要加载目标所在位置并聚焦/高亮；删除和无权限状态仍按后端语义处理。

回复框明确当前回复对象，可取消引用；失败保留输入。作者“楼主”是语境标识，治理角色是权限身份，两者不混淆。引用原文不可绕过被隐藏内容的权限。

### 12.3 手机阅读

内容无左右分栏。底部提供简洁“写回复”入口和主要互动；编辑时打开可完整输入的面板，避免软键盘遮挡。阅读状态的手机导航和详情操作条应合并/替换显示，不叠两条占屏。

## 13. 个人主页与会员中心规格

### 13.1 公开主页

头像、昵称、简介、公开身份、公开勋章与服务端提供的真实关注关系统计。对本人显示“编辑资料”；对他人按权限显示关注/私信；自己的页面不出现关注自己按钮。

信息流身份最多一个标签，优先当前语境中的真实治理身份，再公开用户组，再等级；不要把每个人都标为认证。主页可集中显示公开等级/用户组与最多数枚勋章，更多在同页展开，不把每种能力变成一张卡。

默认页签为“帖子”“资料”；只有确认公开回复接口和可见性过滤完整时才增加“回复”。不默认新增聚合“动态”，不将收藏列为公开页签。

不公开 EXP 明细、精确升级进度、积分余额、积分流水、内部用户组、私有权益、额度、兑换来源、草稿或私信。公开主页中不请求上述数据。个人封面/访客记录不是本期新增范围。

### 13.2 本人会员中心

概览、成长、积分、权益、勋章。等级与 EXP、积分余额与流水、用户组、权益期限和配额分别表达；不能用一个“会员等级”解释全部权限来源。

成长等级来自配置，不固定最多 20 级；最高等级有专门文案。剩余额度、到期时间、失效状态来自真实契约；过期权益不能继续显示有效。

兑换仅在插件安装、启用、可使用时出现。展示消耗积分、权益、有效期和最终确认；扣分和授权仍由服务端幂等事务处理。插件不可用不阻断其他会员信息。

## 14. 搜索、收藏、通知、私信与账号页面

这些页面本轮不重写业务，但必须完成同一导航、字号、按钮、弹层和状态组件迁移。

| 页面 | 必须保留与统一 |
|---|---|
| 搜索 | 主题/版块/用户/标签及已有筛选；URL 状态、分页、关键词高亮和空结果；不能将私有正文混入摘要 |
| 收藏 | 本人列表、取消收藏、返回位置；不开放他人收藏入口 |
| 通知 | 类型、未读、全部已读、目标上下文；目标删除/无权访问不崩溃 |
| 私信 | 对话列表、分页、已读、归档、发送失败；页面切换不得串对话或串用户缓存 |
| 登录/注册 | 邮箱验证、用户名/邮箱登录、会话恢复和真实错误；保持现有安全语义 |
| 账号安全 | 改密、设备会话撤销、OIDC/Passkey/TOTP/恢复码按当前配置显示 |
| 安装向导 | 未安装状态正常可达；UI 改造不破坏初始化和首个管理员流程 |

认证流程只统一外壳与反馈，不重新实现密码学/认证协议，不把未配置的第三方登录或 MFA 画成已经启用。恢复码、密钥不进入截图、日志或一般分析事件。

## 15. 后台工作台及各模块规格

### 15.1 工作台

第一屏优先“我需要处理什么”：待处理举报、待审核编辑、风险告警、服务异常，均以真实能力/权限决定。缺少某个接口则不显示相应数字，而不是填 0。

第二层才是授权范围内的社区摘要、趋势和快捷入口。统计必须注明时间区间、时区、范围和刷新时间；“我的待办”与“全站总量”不可混用。

趋势来自已有聚合接口/报表插件；插件关闭显示未开放，不显示假曲线。浏览统计未闭环不展示总浏览量；不创造注册审核、插件更新提醒等未实现待办。服务状态区只能反映可观测数据及其时间，数据陈旧不显示绿色“正常”。

### 15.2 统一后台工作区模式

页面标题和主操作 → 查询筛选 → 列表/表格 → 对象详情 → 确认或提交 → 精确反馈/审计。

筛选写入安全的 URL 状态，返回后保持；分页模式沿用服务器；批量选择默认仅当前页，切换查询清空或明确重新确认，不能误以为操作全部搜索结果。跨页全选只有已有专门契约时才能提供。

详情桌面用侧抽屉，手机用全屏工作面板；危险操作要求对象、影响范围和原因，不只显示“确定吗”。使用服务器实际权限和 revision；冲突后保留输入但必须刷新确认。

### 15.3 模块细则

| 模块 | 本轮改造焦点 | 必须保留的业务边界 |
|---|---|---|
| 主题管理 | 紧凑列表、版块/状态筛选、正文上下文、移动/隐藏等操作 | 主题可空标题；授权版块作用域；理由与审计 |
| 评论管理 | 带原帖/楼层/引用上下文；可见性处理 | 子回复关系、深链接、删除/隐藏语义 |
| 举报处理 | 队列 → 证据与上下文 → 处理历史 → 组合处置 | 并发处理冲突、重复处置防护、处理通知 |
| 内容审核 | 旧版本/新版本差异，理由和结果 | 待审时保留旧公开版本；插件开关不绕过规则 |
| 风控 | 策略摘要、告警优先级、对象与处理记录 | 只展示实际授权与已有告警动作 |
| 用户 | 搜索、资料、关联内容、限制/恢复与角色调整 | 操作作用域、敏感字段、当前账号/高权账号保护 |
| 版块 | 树形层级、排序、移动、可见性、访问策略、合并/删除影响 | 显隐不等于授权；已有合并/条件回滚能力不重写 |
| 角色与权限 | 能力分组、范围预览、差异确认、人员授权 | 社区组/权益不得悄悄授予治理权限 |
| 会员经济 | 用户选择器 → 当前状态 → 原因 → 操作 → 账本/审计 | 不要求运营手输 UUID；EXP/积分/组/权益分离 |
| 数据 | 时间/范围、口径、空值和延迟状态 | 不混淆增量与累计；插件型报表按启用状态 |
| 品牌 | 现有 Logo/Favicon/颜色/导航/页脚表单与保存反馈 | 保留真实配置上限；首页模式当前固定则不提供假切换 |
| 邮件 | 配置、脱敏、验证/测试反馈（仅已有能力） | 密钥不回显、不写日志；不能把配置成功当投递成功 |
| 插件 | 安装/权限声明/启停/运行状态；高级调用与普通管理分区 | 保留 Wasmtime 权限、配额和 UI 沙箱；关闭宿主状态明确 |
| 运维 | 服务/DB/Outbox/告警，时间与请求关联 | 脱敏；服务失联/数据过期不伪装健康 |

原有“会员经济”拆成多个导航入口不代表新增多套后台服务；仍复用现有 API 和权限。

### 15.4 版块合并与回滚

按用户盘点，合并已有影响预览、主题迁移、审计及满足条件时 24 小时内回滚。本轮只整合其交互，不重新开发另一套合并流程。[P1]

必须展示源/目标对象、实际影响、版本、阻断原因与后台返回的回滚资格；不能仅凭前端计时器显示“可回滚”。过期、资格变化或源/目标已变化时禁用并说明。旧文档中的具体上限以当前契约核实，不能复制为新的硬编码。

## 16. 插件的前台与后台整合

插件功能必须由“宿主启用 + 插件安装启用 + 当前账号权限 + 当前对象允许”共同控制。不能只查看是否存在一段组件代码。

| 插件 | 界面接入点 |
|---|---|
| 成长奖励 | 会员中心的真实规则说明/记录；日界线按现有 UTC 规则解释，不能私自改为浏览器午夜 |
| 单选投票 | 原有主题插槽；一人一票、截止时间与结果策略遵循服务端 |
| 积分兑换 | 本人会员中心与后台兑换配置 |
| 编辑审核 | 编辑状态、旧公开版本、后台差异审核 |
| 帖子补充 | 原有补充内容区域；停用后历史保留规则不丢失 |
| 运营报表 | 后台数据入口和授权趋势 |

每个插件区域有独立加载与错误状态；插件崩溃不阻断原帖、评论或整个后台。样式只能通过宿主支持的主题接口传递，不通过注入任意脚本/CSS 绕过沙箱。

## 17. 技术实施、兼容与范围控制

### 17.1 先映射，再替换

G0 输出真实源码映射：页面 → 现有路由 → 组件 → API 方法 → 权限来源 → 测试 → 插件依赖。不存在的文件不得在计划中假装已存在。

页面不重复取相同用户/版块数据；重用当前请求管理体系，按账号、权限、筛选维度隔离缓存。退出和切换用户清除私有缓存。所有展示适配不改变原始业务存储。

### 17.2 迁移策略

默认在现有路由下逐页原位替换，以小提交和不可变构建产物回退，不长期维护两套完整前端。基础组件和主题先兼容引入；再按路由族推进，每个里程碑保留上一个已验证产物。

只有现有架构已经适合渐进开关时，才复用构建/部署配置控制已验证的 V2 路由族。不要为换皮新增数据库功能开关系统，也不要同时渲染新旧编辑器。

切换仅发生在页面初始化/部署边界，不在用户写到一半时热切编辑器。旧新版兼容读取草稿、URL 和合法偏好。需变更本地草稿格式时，必须版本化、可恢复，不能提前删除旧数据。

### 17.3 API 缺口处理

装饰性数据缺失：移除模块。已有必需能力缺少查询聚合：优先复用现有接口；确需后端补充时建立独立契约变更单，说明授权、版本、OpenAPI 生成与测试，不能伪造端点或让前端绕过服务层。

本轮不改推荐权重、积分账本规则、权益业务规则、插件 ABI、认证协议或数据库领域模型。影响这些内容的需求均另行列项，不以“UI 优化”名义混入。

## 18. 可访问性与性能目标

普通文字对比度目标至少 4.5:1，大号文字至少 3:1；须验证实际颜色组合，而不是认为使用一套色号自动合格。[W1]

本项目将移动主要操作点击区定为至少 44×44 CSS px；这是项目目标。WCAG 2.2 AA 的 2.5.8 最小目标为 24×24 CSS px，另有间距/行内等例外，二者不得混称。[W3]

语义标题、表单标签、图片替代文本、状态播报、键盘路径、焦点返回和非颜色信息表达纳入验收。不是自动扫描零告警就宣称整站 WCAG AA 认证。

真实性能目标采用按桌面/移动分别统计的 p75：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1。这些是上线观测目标，不是当前成绩；本地一次跑分不能替代真实用户样本。[W5]

工程门禁：记录同环境基线与新构建体积；首页不引入完整后台依赖；图片预留尺寸，首屏主要图片不一律懒加载，非首屏按需加载；避免整段富文本在列表重复重处理。压缩脚本体积增长超过基线 10% 时须解释并评审，此 10% 是本项目预算，不是行业标准。

低流量无法形成稳定 p75 时，报告实验室证据和样本不足，不报告“性能指标全达标”。生产观测使用既有合法监测能力；新增分析事件需最小化，不收集正文、私信、密码或草稿。

## 19. 交付范围与完成定义

“完成”包含真实页面、真实动作、权限边界、响应式、错误状态、主题兼容、测试证据、回退入口与交接记录。单张生成图、静态 HTML、测试夹具页面或一个编译成功截图均不足以证明业务完成。

六个里程碑及 24 个任务见 `02-execution-plan.md`；逐项可执行的测试矩阵见 `03-acceptance-matrix.md`。所有未执行任务保持 PLANNED，环境缺失的检查记为 BLOCKED，不冒写 PASS。
