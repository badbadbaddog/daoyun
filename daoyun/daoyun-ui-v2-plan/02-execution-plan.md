# DaoYun UI V2：执行计划与 24 个任务卡

版本：1.0  |  编制日期：2026-09-30  |  状态：所有任务 PLANNED；本次未实施仓库改造。

本文件把 `01-product-and-ui-spec.md` 转为可追踪的工程任务。执行主体沿用 FastSpider_FS，不创建或启动 Codex 会话。编号使用 DYV2-001–DYV2-024，与仓库已有 Task/Phase 编号先映射后使用，不覆盖历史交接。

## 1. 执行硬规则

每个任务按“读交接 → 核对 HEAD/工作树 → 分析影响 → 补失败用例 → 小范围实现 → 定向测试 → 真实页面/API 验收 → 记录证据 → 更新交接”完成。

代码范围限定为现场核实的 DaoYun 项目。不能 `git reset --hard`、`git clean`、覆盖用户未提交改动、全目录 `git add .` 或混入父仓库其他项目。需要隔离时在明确范围内建立独立工作区；依赖未提交改动时记录差异和源代码标识，不能假称干净 HEAD。

不得为赶进度换框架、删测试、关闭 CSRF/权限/MFA、手工修改生成类型或删除旧接口。本方案是规划，不构成自动部署、导入生产数据或向外发送内容的授权。

## 2. 状态机与门禁

`PLANNED → IN_PROGRESS → DONE`；无法完成必需输入/检查时转 `BLOCKED`，解除后回 `IN_PROGRESS`。DONE 必须有真实交付与证据。尚未获准执行的文档任务不会因为写好方案而变 DONE。

## 4. 每个任务共同的完成条件

本任务修改的真实页面有 loading/empty/error/ready 和对应权限状态；320/390/768/1024/1440 布局本任务内验收；关键变更有定向测试，类型与构建通过；影响公共组件时跑受影响页面回归；记录控制台、网络错误及主题兼容结果；新增问题和原基线缺陷分开记录。

每个页面必须有至少一条真实 API 驱动的成功路径。测试夹具可用于视觉/异常/单元测试，必须标明 fixture；不得把 fixture 页面截图当作生产接口接通。

必需依赖阻塞时，只能继续不依赖该项的任务；不能把缺失测试简单标注“不适用”来通过门禁。N/A 必须说明与该任务无关的原因，并区分“没有功能”与“缺少环境”。

必需数据集见验收矩阵：匿名/普通会员/作者/受限会员/版主/局部管理员/超级管理员，公开和受限父子版块，无标题、多图、待审、隐藏/删除、插件开关和计数未知等状态。

视觉夹具可固定时间和计数以减少截图噪声；真实集成测试使用真实事务/授权。测试数据脚本必须可重复、仅针对隔离环境，禁止未校验环境就运行破坏性清库。

## 10. 发布与回退执行规程

候选产物先在测试环境验收。按路由族/小构建渐进替换；界面开关仅选择视图，不改变业务授权。旧/新客户端在同一合法 API 契约下工作，前台与后台可独立回退。

回退触发：正文或草稿丢失、越权/隐私泄露、无法发帖或回复、积分/权益重复操作、旧链接无法访问、关键页面大范围不可用。触发后停止扩大范围，恢复上一个验证构建，保留日志与业务数据并定位根因。

UI 回退不等于数据库回滚。不得因为换回旧页面而恢复旧帖子快照、重算积分或撤销治理；业务撤回必须走正式服务端流程。

旧组件/CSS 仅在实际引用检查、动态/插件入口检查、全量回归和回退产物准备完成后删除。删除与全量重写不在同一个无法审查的大提交中完成。

生产发布必须走用户现有批准流程；本次“制作完整方案”不授权自动上线。无实际生产发布证据的最终状态只能写“开发完成/候选已验证/待部署”，不能写“已上线”。

## 11. 最终交接要求

使用 `05-handoff-template.md`。至少记录完成与未完成任务、真实被测源码标识、分支/HEAD/工作树、修改文件、测试与退出码、实测页面/角色/设备、已知问题、回退位置和下一步。

未提交工作树的被测源码不能只用 HEAD 描述；应记录 diff 摘要/哈希与未跟踪文件清单（脱敏）。提交后区分代码提交与纯文档提交；文档不伪写自身尚未产生的最终 SHA。
