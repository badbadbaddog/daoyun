# ADR-001：认证增强按设备会话、联邦认证与强认证分期

## 状态

已接受

## 日期

2026-08-07

## 背景

DaoYun 已有基于 Cookie 的密码登录、CSRF 防护、哈希会话令牌和账户级会话撤销能力，但尚未向用户提供设备会话可见性。OAuth/OIDC、Passkey 和 MFA 都涉及新的身份绑定、凭据恢复、近期认证与安全审计语义；把它们与会话 UI 一次性合并会扩大不可逆的数据模型和依赖选择风险。

## 决策

先实现设备会话查看和撤销，复用现有 Cookie、CSRF、会话令牌哈希和统一 API 契约。OAuth/OIDC、Passkey 和 MFA 各自作为后续设计及实现切片，必须先确定依赖、账户绑定冲突、恢复与近期认证策略。

设备数据只保存和返回实现会话管理所需的最小受控元数据，绝不返回原始令牌、完整 IP 地址或不受限的请求头。

## 备选方案

### 一次性实现所有认证方式

- 优点：可在单次发布中提供更完整的账户安全功能。
- 缺点：依赖、迁移、恢复和风险控制相互耦合，难以独立验证和回滚。
- 结论：拒绝。

### 只保留管理员会话撤销

- 优点：实现范围小。
- 缺点：用户无法发现异常登录或主动退出遗失设备。
- 结论：拒绝。

### 首先实现设备会话管理

- 优点：复用现有身份边界，直接改善账户控制，并为后续近期认证和设备信任提供基础。
- 缺点：外部认证与 MFA 的实际接入延后。
- 结论：采用。

## 后果

- 会话模型需要增加最小设备元数据和查询索引。
- 用户安全页面成为后续高风险认证操作的入口。
- 联邦认证、Passkey 和 MFA 仍需新的 ADR 和批准后的规格，不能以本 ADR 推断具体 provider、协议参数或恢复策略。
