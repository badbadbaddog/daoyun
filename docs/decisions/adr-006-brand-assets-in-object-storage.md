# ADR-006：品牌二进制资产复用对象存储并由同源 API 提供

## 状态

Accepted

## 日期

2026-08-11

## 背景

站点品牌当前只能保存外部 HTTPS Logo/Favicon URL。自托管部署需要不依赖第三方 CDN 的二进制上传，同时必须避免 SVG/HTML 主动内容、任意存储路径、数据库大对象和跨存储更新留下孤儿文件。

## 决策

- 品牌字节复用附件的本地/S3 对象存储后端，元数据单独保存到 `site_branding_assets`。
- 对象键由资产种类、服务端 SHA-256、服务端生成的 UUIDv7 代际标识和固定扩展名生成；数据库只保存当前对象引用。代际标识避免同内容并发替换在提交后清理阶段误删新一代当前对象。
- 管理 API 使用原始请求体，不引入 multipart 解析依赖；种类在路径枚举中固定。
- 仅接受校验 MIME 和魔数后的 PNG/WebP Logo 与 PNG Favicon，明确拒绝 SVG。
- 公共 API 以同源稳定路径读取当前资产；响应使用服务端保存的 MIME、`nosniff` 和缓存头。
- 新对象先写入，数据库事务提交后再清理旧对象；数据库失败会清理新对象。相同摘要替换天然幂等。

## 备选方案

### 直接把字节保存到 PostgreSQL

- 优点：单一事务简单。
- 缺点：放大数据库、备份和连接带宽，绕开现有对象存储能力。
- 结论：拒绝。

### 继续只支持外部 URL

- 优点：实现最小。
- 缺点：不满足离线与自托管需求，外部资产可变且带来隐私请求。
- 结论：拒绝。

### 允许 SVG

- 优点：缩放质量和体积好。
- 缺点：主动内容与复杂解析面不符合当前最小安全边界。
- 结论：拒绝；未来如需要，应先建立可信 SVG 清洗流水线。

## 后果

- 不新增第三方运行时依赖，并统一本地与 S3 部署行为。
- 数据库事务无法原子提交对象存储写入，因此实现显式补偿清理并以测试覆盖。
- 同源资产 URL 可长期稳定，字节缓存可由摘要和缓存头控制。
